# FlyMail V1 UI on V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Keep every V2 feature and API contract while restoring the complete V1 visual shell and design language.

**Architecture:** Keep `AppV2.vue`, the V2 router, feature state, realtime client and `/api/v2` calls. Add a V2-aware sidebar that uses the V1 shell classes, load the V1 design-system styles in the formal entry, and add one compatibility stylesheet for V2 feature markup.

**Tech Stack:** Vue 3, TypeScript, Vue Router, Pinia, Node test runner, Vite, Docker, MySQL 8.0.

## Global Constraints

- Do not switch the formal entry back to legacy `App.vue`.
- Do not change backend APIs, schema, authentication, Worker behavior or `/data` paths.
- Do not add or upgrade production dependencies.
- Keep desktop, tablet, mobile, keyboard focus, dark theme and reduced motion behavior.
- Use `/Docker/flymail/data` only for the final existing container; all smoke tests use temporary data.
