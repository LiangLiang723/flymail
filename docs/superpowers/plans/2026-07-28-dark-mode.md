# FlyMail Dark Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a persistent three-state appearance setting with browser-following as the default and complete dark styling for the FlyMail shell and shared design system.

**Architecture:** A standalone theme controller owns preference parsing, persistence, DOM class application, and system media-query listening. Vue initializes it before mount and the Settings view consumes the same controller. Existing CSS variables become the theme boundary; shell hard-coded colors are replaced with those variables.

**Tech Stack:** Vue 3, TypeScript, CSS custom properties, browser `localStorage`, `matchMedia`, Node built-in test runner.

## Global Constraints

- Default preference is `system`.
- Supported values are exactly `system`, `light`, and `dark`.
- Storage key is exactly `flymail_theme`.
- Dark mode uses the existing root class `.dark`.
- No new production dependency and no database change.
- Theme preference remains browser-local and must apply before Vue mounts.
