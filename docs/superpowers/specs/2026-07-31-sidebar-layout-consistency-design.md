# 侧边栏与全局页面间距一致性设计

## 目标

修复桌面端侧边栏折叠过程中的图标重叠和折叠态偏心问题，并建立所有一级页面统一的外层间距规则，避免邮件、联系人、写信等工作区贴边，而聚合收件箱、设置、个人资料等页面保留间距的割裂感。

## 已确认根因

1. 主导航按钮设置了左右各 `8px` 外边距，但图标列仍固定为 `72px`。折叠后按钮实际只有 `56px` 宽，图标却按 `72px` 列居中，因此图标中心落在侧栏中心右侧 `8px`。
2. 底部通知按钮位于左右各 `8px` 的容器内，仍复用 `72px` 图标列；用户资料按钮还使用 `64px + 文本 + 28px` 三列。折叠时这些列宽超过可用宽度，头像、文字和箭头发生挤压或重叠。
3. 顶部品牌图标固定在左侧 `72px` 轨道内，折叠按钮绝对定位在侧栏右边。侧栏宽度从 `248px` 动画缩到 `72px` 时，按钮会横穿品牌图标位置，造成短暂重叠。
4. 管理页和文档页由 `PageFrame` 子内容提供 `20px` 间距，而工作区和分栏页直接贴边。另有多个页面在移动端自行给页面根节点增加 padding，造成模板间距之外的二次缩进。

## 方案比较

### 方案 A：逐页面和逐按钮补偏移

在每个折叠按钮上单独增加 `translateX`，并分别给邮件、联系人等页面添加 margin。改动最少，但会继续保留重复规则，后续新增页面或按钮很容易再次偏移。

### 方案 B：统一侧栏几何和 PageFrame 外层契约（采用）

侧栏保留 `72px` 固定图标轨道。所有带 `8px` 内缩的按钮统一使用 `56px` 图标列，使图标中心始终位于 `36px`。折叠态立即隐藏文字和箭头，顶部品牌先淡出，再由折叠按钮占据轨道中心。页面间距由 `PageFrame` 模板集中负责：桌面端工作区和分栏页统一获得 `20px` 外层间距，管理页和文档页继续使用现有 `20px` 内容间距；移动端工作区保持边到边，管理和文档页面使用 `16px` 紧凑间距。

### 方案 C：重写侧栏为固定轨道加独立内容面板

新增两层 DOM，将 `72px` 图标轨道和 `176px` 文字面板分别动画。结构最彻底，但需要重写侧栏、移动抽屉和账号菜单定位，超出本次修复范围。

## 侧边栏设计

- `--app-icon-rail` 保持 `72px`。
- `--sidebar-item-inset` 固定为 `8px`，内缩按钮的可用图标列为 `56px`。
- 主导航、通知按钮和头像按钮在展开与折叠过程中使用同一条 `56px` 图标列，不再随侧栏宽度重新计算中心点。
- 折叠态头像按钮网格改为 `56px 0 0`，头像之外的昵称和箭头立即隐藏。
- 顶部折叠时品牌图标快速淡出，折叠按钮在 `72px` 轨道内居中；展开时品牌图标延迟出现，避免与仍在移动的按钮交叉。
- 激活背景继续保留 `8px` 内缩和圆角，激活指示条相对 `56px` 图标列定位。
- 减少动态效果模式不执行位移动画，但仍保持最终几何位置正确。

## 页面间距设计

- 桌面端一级页面统一以侧栏边界后 `20px` 作为首个可见内容起始线。
- `management` 和 `document` 模板：页头与内容继续使用 `var(--page-padding)`。
- `workspace` 和 `split` 模板：`page-frame__body` 使用 `var(--page-padding)` 外边距，内部邮件壳、联系人分栏、备份和写信区域占满剩余空间。
- 写信页面的 `page-frame__body` 作为统一面板表面，补齐边框、圆角、背景和阴影。
- 删除各视图对一级页面根节点设置的 padding，所有外层空间只允许由页面模板控制。
- `max-width: 960px` 时，工作区和分栏页恢复边到边布局；管理页和文档页由现有紧凑变量统一为 `16px`。

## 测试与验收

1. 前端静态回归测试验证侧栏内缩按钮使用 `56px` 图标列、折叠头像网格收缩、顶部品牌与按钮互斥显示。
2. 页面模板测试验证桌面工作区和分栏页拥有统一外边距，移动端明确取消该外边距。
3. 扫描所有一级视图，禁止页面根节点声明 padding、margin 或纵向滚动。
4. 运行全部前端测试和生产构建。
5. 运行后端完整测试、Shell、Compose、Git diff 检查。
6. 构建并启动 `0.0.20` 临时容器，验证健康、持久化、MySQL 和日志脱敏；随后安全替换当前 `flymail` 容器，不修改 `/Docker/flymail/data`。
