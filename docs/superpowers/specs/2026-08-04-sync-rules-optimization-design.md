# FlyMail 同步规则优化设计

## 目标

将实时监听、周期兜底、手动刷新、摘要补齐和历史同步收敛为可预测的调度规则，降低重复 IMAP 连接和大邮箱查询开销，消除无执行者任务、文件夹监听掉队和长时间刷新卡住问题。

## 非目标

- 不修改认证方式。
- 不迁移或删除 MySQL、邮件、附件和 `/data` 数据。
- 不更换 FastAPI、Vue 3、MySQL 或现有 Provider 实现。
- 不引入新的生产依赖。
- 不改变用户配置字段 `poll_interval_seconds` 的范围 `5..3600`。

## 运行时协调

新增 `backend/services/sync_coordinator.py`，按账号协调三类操作：

- `interactive`：手动刷新、用户主动读取远端详情。没有独占任务时立即执行，优先于尚未开始的后台任务。
- `background`：周期对账、实时事件后的缓存同步、摘要补齐。账号存在交互操作、独占等待或独占执行时跳过，不排队堆积。
- `exclusive`：历史同步、清空账号缓存、清空文件夹缓存和删除账号。等待已开始的后台操作结束，随后阻止新的交互和后台远端同步。

协调器仅保存内存状态。容器重启后状态自然清空，不新增数据库表。

`MailSyncService.suspend_account()` 改为引用计数。多个独占任务重叠时，只有最后一个任务结束才恢复实时监听，避免一个任务过早恢复连接。

## 实时监听和周期兜底

### IDLE Provider

Gmail、QQ、Outlook 继续为核心文件夹维持独立 IDLE 连接。周期完整对账不再沿用默认 10 秒，而使用：

```text
max(用户配置间隔, 180 秒)
```

### iCloud Poll Provider

iCloud 保留用户配置的实时 STATUS 间隔，周期完整对账使用：

```text
max(用户配置间隔, 120 秒)
```

单个文件夹 Poll 连接断开后，只重建该文件夹连接，不等待全部文件夹同时断开。

### 非 IDLE Provider

网易、新浪和通用 IMAP 不再对每个文件夹分别等待一个完整轮询周期。每轮执行一次批量 STATUS 扫描全部监听文件夹，比较总数和未读数后统一休眠 `poll_interval_seconds`。

- 总数增加：增量同步该文件夹并推送新邮件。
- 总数减少：清理本地缓存并刷新列表。
- 未读数变化：同步已读状态并刷新列表。
- 批量 STATUS 失败：进入统一重连与退避流程。

周期完整对账使用：

```text
max(用户配置间隔, 60 秒)
```

### 周期调度

全局周期循环不再串行等待全部账号。每个到期账号创建独立任务，并用 `asyncio.Semaphore(3)` 限制最多三个账号并发。一个账号同一时间最多一个周期任务；任务完成后才计算下一次到期时间。

所有 Provider 的监听异常统一增加连续失败次数。前三次每 5 秒重试，随后指数退避至 300 秒；成功连接后清零。

## 手动刷新

`GET /api/messages/refresh` 使用 45 秒超时。超时、历史同步独占或远端连接暂不可用时立即返回本地缓存，并在 `error` 字段提供明确说明，不让刷新按钮无限等待。

成功刷新仍只等待当前文件夹第一页和计数；缺失摘要进入后台任务。后台摘要任务按账号协调规则去重，交互操作到来时在批次边界让出执行权。

## 历史同步生命周期

历史同步继续按“最近摘要、正文和内嵌图片、已读状态”三阶段执行，但修改以下规则：

- 正文阶段连续无进度时，在同一后台 worker 内按 2、5、10 秒进行三次有限重试。
- 三次后仍有未处理邮件，任务直接标记 `failed`，保留断点和明确错误；不再创建没有 worker 的 `pending`。
- 每个正文批次检查暂停状态。
- 阶段、文件夹和正文批次变化时推送 `history_sync_updated` WebSocket 消息。
- 同步管理页收到消息后刷新；15 秒轮询仅作为断线兜底，替代活动任务期间每 3 秒轮询。

## 查询和大邮箱优化

- 同步管理接口一次加载账号全部任务、文件夹统计和缓存计数，不再对每个文件夹分别查询任务、统计和缓存数量。
- 最近邮件同步仅查询当前远端页 UID 是否已缓存，不再每轮加载整个文件夹全部本地 UID。
- 历史最近摘要阶段采用相同的分页 UID 存在性查询。
- 已读状态校正按本地 UID 每 1000 条分页处理，不再一次加载最多 10000 条完整邮件记录。
- 完整远端 UID 对账仍仅用于显式摘要补齐或检测到删除的低频路径。

## 前端和文档

账号编辑页将字段说明改为“非 IDLE 实时检查间隔”，并明确 IDLE Provider 使用实时通知、完整兜底最低三分钟。同步管理页处理 `history_sync_updated`，将轮询兜底改为 15 秒。

README 同步说明差异化间隔、45 秒刷新超时、历史同步有限重试和 WebSocket 进度规则。
