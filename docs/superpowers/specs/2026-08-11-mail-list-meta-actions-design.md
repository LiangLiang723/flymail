# FlyMail 邮件列表右侧元信息操作区设计

## 1. 背景

当前 `0.0.53` 邮件列表中，附件图标和验证码复制图标不属于同一套布局：

- 附件回形针位于主题内容末尾，尺寸为 12px，并带少量左边距。
- 验证码复制按钮位于日期左侧，尺寸为 28×28px，并通过左右 margin 自己撑开空间。
- 日期拥有固定宽度和额外左 padding。

因此有验证码、附件、两者同时存在或都不存在时，邮件行右侧的视觉节奏会发生明显变化。附件图标看起来像主题的一部分，而复制图标又像独立工具按钮，和日期之间缺少统一的元信息布局。

## 2. 目标

把附件、验证码复制和日期统一为一个稳定的右侧元信息区，同时满足：

1. 日期永远最右且各行对齐。
2. 图标区不预留空槽位，只有实际存在的图标才占空间。
3. 同时存在复制和附件时，固定顺序为：`复制 → 附件 → 日期`。
4. 只有附件时：`附件 → 日期`。
5. 只有复制时：`复制 → 日期`。
6. 附件只要存在，就始终是图标区最靠近日期的图标。
7. 主题获得连续、干净的可收缩空间，不再把附件图标嵌在主题末尾。
8. 不改变验证码识别、附件下载、日期格式、搜索位置、未读状态或邮件打开行为。

## 3. 桌面布局

邮件行逻辑顺序调整为：

```text
发件人 | 未读信封 + 主题（弹性） | 元信息图标区 | 日期
```

右侧具体表现：

```text
无图标：   主题………………………………………  14:00
只有附件： 主题………………………………  📎  14:00
只有复制： 主题………………………………  ⧉   14:00
两个都有： 主题……………………………  ⧉  📎  14:00
```

### 3.1 `mail-meta-actions`

新增一个页面内结构类：

```text
mail-meta-actions
```

职责只包含右侧可选图标，不包含日期。

约束：

- `display: inline-flex`
- `align-items: center`
- `flex-shrink: 0`
- 图标之间固定 `gap: 6px`。
- 主题到图标区固定 8px；图标区到日期固定 8px。
- 没有图标区时，主题到日期仍保持 8px，因此四种组合使用同一节奏。
- 容器本身不设置固定宽度，不为空图标预留槽位。
- 当没有附件和验证码时，不渲染该容器，主题直接延伸到日期前。

### 3.2 图标顺序

模板顺序固定：

1. `verification-code-copy`
2. `attachment-indicator`
3. `mail-date`

不允许通过 CSS `order` 动态重排，顺序直接由 DOM 保证。

## 4. 验证码复制图标

验证码复制按钮继续保持当前交互能力：

- 纯图标，无可见“复制验证码”文字。
- `title="复制验证码"`。
- 保留可访问 `aria-label`。
- 点击只复制验证码，不打开邮件。
- 保留 `focus-visible`。
- 保持约 28×28px 的交互按钮尺寸。

布局调整：

- 删除当前 `margin: 0 8px`。
- 不再依靠按钮自己的 margin 控制与附件/日期的间距。
- 间距全部由 `mail-meta-actions` 和日期之间的统一布局控制。

视觉上复制 SVG 继续约 15px。

## 5. 附件图标

当前 `.att-badge` 从 `.mail-main-row` 的主题末尾移出，进入 `mail-meta-actions`。

附件图标是状态指示，不是按钮：

- 不增加 hover 背景。
- 不改变点击行为；点击邮件行仍按原行为打开邮件。
- 不增加独立附件下载入口。
- 使用与复制图标静态状态接近的 tertiary 文本色。

尺寸从当前 12px 精确调整为 `15px × 15px`，与复制按钮内部的 15px SVG 使用同一图形尺寸；附件本身仍不是 28px 按钮，不增加按钮背景或独立点击区域。

## 6. 日期

日期继续保持最右固定列和 `flex-shrink: 0`。

当前日期自身通过 `padding-left: 8px` 与前方内容分隔，调整后：

- 删除当前用于补偿的 `padding-left: 8px`。
- 日期统一使用 `margin-left: 8px` 与前方内容分隔。
- `mail-meta-actions` 自身使用 `margin-left: 8px` 与主题分隔。
- 当没有图标区时，日期的 `margin-left: 8px` 直接形成主题到日期的间距。
- 日期宽度继续保持当前固定桌面宽度，避免各行日期左右跳动。

因此桌面只保留三个间距来源：图标区内部 `gap: 6px`、主题到图标区 8px、前方内容到日期 8px；不再叠加复制按钮 margin 或日期 padding。

## 7. 移动端

移动端继续使用现有两行 grid，不推倒重做。

当前 grid：

```text
"select sender date"
"select info code"
```

本轮需要把附件图标也归入移动端右下角元信息区域，而不是继续贴在主题末尾。

设计要求：

- 日期仍在右上。
- 可选图标区在右下。
- 同时存在时仍为 `复制 → 附件`，附件靠右。
- 只有附件时附件占右下。
- 只有复制时复制占右下。
- 图标区不得与日期重叠。
- 390×844 不出现页面级横向滚动。
- 移动端不为缺失图标预留空槽。

实现可以把现有 `code` grid area 重命名/泛化为 `meta`，但只在 `MailList.vue` 页面内部修改，不新增公共布局抽象。

## 8. 不做的事情

本轮明确不做：

- 不改变验证码识别规则。
- 不改变附件检测逻辑或下载逻辑。
- 不改变日期格式和排序。
- 不改变未读蓝点、未读信封和字重。
- 不改变发件人 165px / 24px 的当前桌面布局。
- 不移动搜索栏。
- 不新增公共组件或第三方依赖。
- 不给没有附件/验证码的邮件预留固定图标占位。
- 不把附件图标做成按钮。

## 9. 预计实现文件

## 10. TDD 验收契约

实现前先新增失败测试，锁定：

1. `.att-badge` 不再出现在 `.mail-main-row` 内。
2. 新的 `mail-meta-actions` 按 DOM 顺序包含：验证码复制按钮在前、附件图标在后。
3. `mail-date` 位于 `mail-meta-actions` 之后。
4. `mail-meta-actions` 只在至少存在附件或验证码时渲染。
5. 复制按钮没有额外左右 margin。
6. 附件图标尺寸锁定为 `15px × 15px`。
7. 桌面图标区固定 `gap: 6px`，主题到图标区 8px，图标区/主题到日期 8px，日期仍固定最右。
8. 移动端使用统一 meta grid area，不再把附件放在主题文本流里。
9. 390px 移动端继续 `overflow-x: hidden`，页面无横向溢出。

## 11. 浏览器验收

使用真实 production build + 安全模拟 API 数据，至少包含四行：

1. 无附件、无验证码。
2. 只有附件。
3. 只有验证码。
4. 同时有附件和验证码。

### 1440×900 / 1920×1080

确认：

- 日期四行严格对齐。
- 只有附件时附件紧邻日期左侧。
- 只有复制时复制紧邻日期左侧。
- 两者都有时顺序是复制、附件、日期。
- 附件不再贴在主题文字末尾。
- 主题长度变化不会把图标或日期挤掉。
- 图标之间和图标到日期的间距一致、自然。

### 390×844

确认：

- 日期在右上，元信息图标在右下。
- 两图标同时存在时复制在左、附件在右。
- 没有图标时不保留空白轨道。
- 无横向滚动或图标重叠。

### 200% 等价场景

确认：

- 元信息图标和日期保持可访问。
- 主题正常收缩。
- 无页面级横向溢出。

## 12. 验收标准

1. 附件图标从主题区移到统一右侧元信息区。
2. 验证码复制图标也属于同一元信息区。
3. 同时存在时顺序严格为 `复制 → 附件 → 日期`。
4. 只有附件时附件是日期左侧唯一图标。
5. 只有复制时复制是日期左侧唯一图标。
6. 附件存在时始终最靠近日期。
7. 日期各行固定对齐。
8. 没有图标时不预留空槽位。
9. 复制按钮不再依赖自身左右 margin 控制布局。
10. 附件和复制图标视觉尺寸更协调，但附件仍是非交互状态图标。
11. 桌面、移动端和 200% 等价场景无横向溢出。
12. 不改变验证码识别、附件逻辑、搜索、未读状态、发件人列或正式数据。
