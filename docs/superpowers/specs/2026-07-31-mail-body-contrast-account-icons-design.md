# 邮件正文主题对比度与邮箱账号图标设计

## 1. 目标

本设计同时解决两个用户可见问题：

1. 邮件正文携带固定字体颜色时，在 FlyMail 深色或浅色主题中可能与正文背景对比不足，导致文字难以阅读。
2. 每个邮箱账号只能显示服务商默认图标，用户无法上传自己的图标或从 FlyMail 内置图标库中选择。

交付目标是：邮件正文在浅色和深色主题下都保持可读，同时尽量保留原邮件的品牌色和排版；每个邮箱账号支持“服务商默认、FlyMail 内置、用户上传”三种图标来源，并提供与现有界面一致的图片裁剪流程。

## 2. 范围与非目标

### 2.1 本次范围

- 邮件详情正文和本地备份正文使用同一套主题感知颜色转换。
- HTML 邮件中的文本颜色、元素背景颜色和旧式 `font color` / `bgcolor` 参与对比度分析。
- 纯文本邮件继续使用 FlyMail 主题正文颜色。
- 邮箱账号支持：
  - 恢复服务商默认图标；
  - 选择 FlyMail 内置图标；
  - 上传图片并在浏览器中裁剪；
  - 在所有展示账号身份的位置复用同一个最终图标。
- 自定义图标持久化到 `/data/flymail/files/account-icons/`。
- 数据、接口和文件访问必须按当前用户隔离。

### 2.2 非目标

- 不修改数据库中保存的原始邮件正文。
- 不改变发件人设置的图片、Logo 或内嵌图片像素颜色。
- 不保证每封营销邮件的完整品牌视觉与原客户端一模一样；可读性优先于低对比度装饰色。
- 不支持 GIF 动画、SVG 上传或任意外部图片 URL。
- 不保存用户上传的原始大图，只保存裁剪后的 WebP。
- 不为文件夹、联系人或用户头像增加同类图标配置。

## 3. 邮件正文颜色适配

### 3.1 根因

`frontend/src/utils/sanitize.ts` 当前允许邮件 HTML 保留 `style`、`color` 和 `bgcolor`。邮件正文容器虽然使用 FlyMail 的主题颜色，但邮件节点中的内联颜色优先级更高。例如黑色签名文字在深色正文面板上仍然保持黑色，因此几乎不可见。

只给正文容器添加 `color: var(--ui-text-1) !important` 会破坏品牌色，并且无法正确处理带自定义背景色的表格或签名块，所以需要在安全渲染阶段对前景色和背景色成对分析。

### 3.2 渲染架构

新增一个专门的邮件颜色适配模块，职责边界如下：

- `sanitizeHtml()`：继续负责 XSS 清理和标签/属性白名单。
- `renderMailBody()`：继续输出与主题无关的安全正文，供回复、转发和 PDF 导出使用。
- 邮件颜色适配模块：接收已经净化的 HTML，解析颜色并生成浅色、深色两套安全颜色。
- `renderThemedMailBody()`：在 `renderMailBody()` 结果上增加阅读视图专用的双主题颜色变量。
- 邮件详情与备份详情：只消费 `renderThemedMailBody()`，不再各自实现颜色修复。

颜色转换只发生在阅读视图的浏览器渲染结果中，不回写缓存正文。回复、转发和 PDF 导出继续使用不含 FlyMail 主题变量的 `renderMailBody()`，避免把应用内部 CSS 变量发送给收件人或写入导出文件；编辑器本身使用编辑器主题颜色，不应用阅读视图的双主题属性。

### 3.3 颜色输入

适配模块处理以下来源：

- `style="color: ..."`
- `style="background-color: ..."` 和 `style="background: ..."` 中可可靠解析的纯色
- `<font color="...">`
- `color="..."`
- `bgcolor="..."`

支持浏览器可解析的十六进制、`rgb()`、`rgba()`、`hsl()`、`hsla()` 和命名色。透明前景色、渐变、背景图片和无法解析的颜色不参与计算；这些情况使用继承后的有效颜色或 FlyMail 正文背景作为回退。

### 3.4 对比度公式

颜色先转换到 sRGB，再计算线性通道：

```text
channel <= 0.04045
  ? channel / 12.92
  : ((channel + 0.055) / 1.055) ^ 2.4
```

相对亮度：

```text
L = 0.2126 × R + 0.7152 × G + 0.0722 × B
```

对比度：

```text
contrast = (max(L1, L2) + 0.05) / (min(L1, L2) + 0.05)
```

普通正文、签名和表格文字的最低目标为 `4.5:1`。字号和字重来自不可信的邮件 HTML，第一版不为“大号文字”放宽到 `3:1`，避免错误判断造成不可读。

### 3.5 转换规则

对每个带明确文本颜色的元素分别生成浅色和深色结果：

1. 确定当前元素的有效背景：优先使用元素自身纯色背景，其次向父元素查找纯色背景，最终回退到 FlyMail 浅色或深色正文面板背景。
2. 将带透明度的前景或背景与下层背景做 alpha 合成。
3. 原颜色达到 `4.5:1` 时保持不变。
4. 原颜色不足 `4.5:1` 时，保持原色相和饱和度，在 HSL 明度轴上分别向黑或向白搜索。
5. 两个方向都能达标时，选取与原颜色色差更小的一项；只有一个方向达标时使用该方向。
6. 极端情况下无法在保留色相后达标，则使用对应主题的 `--ui-text-1`。
7. 链接仍保留链接语义；低对比度链接转换后还要满足与背景 `4.5:1`，并继续使用下划线或现有链接样式提供非颜色提示。

对邮件自带明确背景色的元素，背景色默认保留。若该背景本身带透明度，则先与其主题下的父背景合成后计算文字颜色。这样可以保留公司签名色块、表格和按钮，同时保障内部文字可读。

### 3.6 输出格式与主题切换

颜色适配模块不依赖当前主题直接写死一个颜色，而是在需要修复的元素上写入双主题 CSS 变量，例如：

```html
<span
  class="flymail-mail-color"
  style="--flymail-mail-color-light:#3a3a3c;--flymail-mail-color-dark:#f0f0f2"
>
```

全局样式根据根节点主题选择：

```css
.flymail-mail-color {
  color: var(--flymail-mail-color-light) !important;
}

:root.dark .flymail-mail-color {
  color: var(--flymail-mail-color-dark) !important;
}
```

背景需要双主题修复时使用独立的背景变量和类名。主题切换不需要重新请求邮件或修改 DOM 内容。

为避免邮件作者的选择器覆盖修复结果，适配后的颜色声明使用受控类和 `!important`。该规则只作用于邮件正文容器内部，不泄漏到 FlyMail 其他界面。

### 3.7 安全与性能

- 必须先 DOMPurify 净化，再通过 `DOMParser` 处理颜色，最后再次确保输出不引入事件属性、脚本或不受控 URL。
- 不执行邮件 CSS，不读取远程样式表，不解析 `@import`。
- 只遍历正文元素一次；颜色解析结果按颜色字符串和背景组合做内存缓存。
- 对超长邮件设置合理的节点处理上限。超过上限的剩余节点使用正文主题颜色兜底，不阻塞界面。
- 正文图片、SVG 以外的图像资源、附件和 Logo 不应用滤镜或颜色反转。

## 4. 邮箱账号图标

### 4.1 图标模式

每个账号保存一种图标模式：

- `default`：使用该账号服务商的默认图标。
- `preset`：使用 FlyMail 内置图标，值为稳定的预设 ID。
- `upload`：使用当前账号上传并裁剪后的 WebP。

恢复默认图标会把模式改为 `default`，清空预设 ID，并安全删除该账号原有上传文件。选择内置图标时也删除不再使用的上传文件，避免孤儿文件。

### 4.2 数据模型

在 `accounts` 表进行可逆、增量式字段扩展：

- `icon_type VARCHAR(32) NOT NULL DEFAULT 'default'`
- `icon_value VARCHAR(255) NOT NULL DEFAULT ''`

约束含义：

- `default`：`icon_value` 为空。
- `preset`：`icon_value` 为内置图标 ID。
- `upload`：`icon_value` 为空，文件路径由服务器根据当前用户 ID 和账号 ID 确定，前端永远不会接触绝对路径。

现有账号迁移后全部保持 `default`，不改变当前显示效果。`Account` 模型、账号列表响应和前端账号类型同步增加图标字段。

### 4.3 文件存储

裁剪后的图片保存到：

```text
/data/flymail/files/account-icons/<user_uid>/<account_id>.webp
```

规则：

- 文件名只由服务器端用户 ID 和账号 ID生成，不使用上传文件名。
- 最终格式固定为 WebP，尺寸固定为 `256×256`。
- 原始上传文件不落盘。
- 新文件先写入同目录临时文件，验证成功后原子替换。
- 删除邮箱账号时同步删除图标文件和用户空目录。
- `ensure_data_dirs()` 创建账号图标根目录。

### 4.4 内置图标库

第一版内置图标采用仓库内的受控 SVG，不允许用户输入 SVG。稳定 ID 如下：

- `mail-purple`
- `mail-blue`
- `mail-green`
- `work`
- `personal`
- `school`
- `team`
- `star`

服务商默认图标不重复放入预设库；用户通过“恢复默认图标”回到 Gmail、Outlook、QQ、网易、iCloud、新浪或通用邮箱的默认图标。

预设图标 ID 是持久化接口，后续可以新增，但不能静默改变已有 ID 的含义。遇到未知 ID 时前后端均回退到服务商默认图标。

### 4.5 API

账号列表响应增加：

```json
{
  "icon_type": "default | preset | upload",
  "icon_value": "",
  "icon_url": ""
}
```

其中 `icon_url` 仅在 `upload` 模式且文件存在时返回受保护的账号图标地址，并带账号更新时间版本参数以避免旧缓存。

新增账号图标操作：

- `PUT /api/accounts/{account_id}/icon/preset`
  - 请求：`{"preset_id":"work"}`
  - 校验账号属于当前用户，校验预设 ID。
- `POST /api/accounts/{account_id}/icon/upload`
  - `multipart/form-data` 上传裁剪后的 WebP。
  - 校验账号属于当前用户。
- `DELETE /api/accounts/{account_id}/icon`
  - 恢复服务商默认图标并删除上传文件。
- `GET /api/accounts/{account_id}/icon`
  - 仅允许账号所属用户读取上传图标。
  - 返回 `image/webp` 和私有缓存头。

现有 `PUT /api/accounts/{account_id}` 继续只更新备注、分组、隐藏邮箱和轮询间隔，避免把二进制上传与普通表单更新耦合。

### 4.6 上传与裁剪界面

账号编辑对话框新增“邮箱图标”区块，视觉完全复用当前设计系统：

- 当前图标大预览。
- “选择内置图标”按钮。
- “上传图片”按钮。
- 仅在非默认模式下显示“恢复默认图标”。

选择文件后打开与现有对话框一致的裁剪弹窗：

- 固定 `1:1` 裁剪框。
- 图片可拖动调整位置。
- 缩放滑杆。
- 鼠标滚轮缩放。
- 移动端双指缩放和单指拖动。
- 显示 `32px` 和 `48px` 两种最终效果预览。
- “重新选择”“取消”“使用此图标”三个操作。
- 支持 Escape 关闭、键盘焦点约束和减少动态效果。

浏览器使用 Canvas 输出 `256×256 image/webp`。服务端必须重新用 Pillow 解码、应用 EXIF 方向、转为 RGB/RGBA、限制像素和文件大小，并再次缩放为 `256×256 WebP`，不能信任前端结果。

上传输入限制：

- 接受 JPEG、PNG 和 WebP。
- 原始文件最大 `10 MB`。
- 解码后的最大像素总数 `40,000,000`。
- 拒绝 SVG、GIF、损坏图片和伪造 MIME。

### 4.7 统一展示组件

新增统一账号图标组件，输入账号的 `provider`、`icon_type`、`icon_value` 和 `icon_url`，内部处理：

1. 有效上传图标；
2. 有效内置预设；
3. 服务商默认图标。

组件负责统一圆角、尺寸、加载失败回退和无障碍文本。以下区域必须改为使用该组件，而不是继续直接调用 `providerIcon()`：

- 账号管理账号卡片；
- 邮件管理账号列表；
- 移动端账号列表；
- 邮件备份账号列表；
- 聚合收件箱中展示账号身份的区域；
- 后续新增的账号身份展示位置。

服务商分组标题和“添加邮箱平台”选择器仍显示服务商默认图标，因为它们代表平台，不代表某个用户账号。

### 4.8 一致性与实时更新

保存预设、上传或恢复默认后：

- 接口返回最新账号图标字段。
- 前端更新 Pinia 中对应账号对象并重写 sessionStorage 缓存。
- 当前页面中的所有账号图标立即刷新，不要求重新登录。
- 上传 URL 使用版本参数；重新上传时不会显示浏览器缓存的旧图片。

## 5. 错误处理

### 5.1 邮件颜色

- 无法解析的颜色不抛出页面错误，使用继承颜色或主题正文色。
- 单个异常节点不能导致整封邮件无法显示。
- 颜色适配失败时回退到已经净化的正文，并在开发日志中记录不包含邮件正文的简短错误。

### 5.2 账号图标

- 不支持的图片类型：提示“仅支持 JPG、PNG 或 WebP 图片”。
- 文件过大：提示“图片不能超过 10 MB”。
- 图片损坏或解码失败：提示“无法读取该图片，请更换文件”。
- 账号不属于当前用户：返回 404，避免泄露账号存在性。
- 上传文件丢失或内置 ID 无效：界面自动回退服务商默认图标，并允许用户重新设置。
- 保存失败时保留当前弹窗和裁剪状态，用户可重试，不提前覆盖正在使用的旧图标。

## 6. 测试策略

### 6.1 前端单元与契约测试

邮件颜色转换至少覆盖：

- 黑字在深色背景上转换到 `4.5:1` 以上。
- 浅灰字在浅色背景上转换到 `4.5:1` 以上。
- 已达标的品牌色保持不变。
- 带明确深色或浅色背景的签名块以自身背景计算。
- `font color`、内联 `color`、`bgcolor` 和透明色。
- 无效颜色、渐变和超长节点列表安全回退。
- 图片不被添加滤镜或颜色转换。
- 切换根主题后使用对应的浅色/深色变量。

账号图标至少覆盖：

- 统一组件的上传、预设、默认及加载失败回退优先级。
- 未知预设回退默认图标。
- 裁剪数学：拖动边界、缩放上下限、居中初始状态和 `256×256` 输出。
- 账号编辑弹窗包含预设选择、上传裁剪和恢复默认入口。
- Pinia 与 sessionStorage 在图标更新后同步。
- 邮件、备份、聚合和移动端账号区域都使用统一组件。

### 6.2 后端测试

- 数据库迁移为现有账号添加默认图标字段且幂等。
- 账号列表返回安全的图标字段，不返回绝对文件路径。
- 上传、预设、恢复默认均验证当前用户所有权。
- Pillow 正规化输出 `256×256 WebP`。
- JPEG EXIF 方向正确处理。
- 拒绝 SVG、GIF、损坏数据、超大文件和像素炸弹。

- 切换预设或恢复默认会清理旧上传文件。
- 删除账号会清理账号图标。
- 跨用户读取图标返回 404。

## 8. 验收标准

1. 截图中深色背景上的黑色签名文字变得清晰可读，对比度不低于 `4.5:1`。
2. 浅色主题下原本过浅的文字同样自动调整，不出现“只修深色模式”的偏差。
3. 已有高对比度品牌颜色和带背景签名块尽量保持原样，图片与 Logo 不反色。
4. 主题切换即时生效，不重新请求或修改原始邮件。
5. 每个邮箱账号可上传图片并通过一致的裁剪弹窗调整为正方形图标。
6. 每个邮箱账号可选择内置图标，也可恢复服务商默认图标。
7. 自定义图标在账号管理、邮件管理、移动端、备份和聚合收件箱中保持一致。
8. 图标按用户和账号隔离，跨用户不能读取或修改。
9. 容器重启和替换后图标不丢失，删除账号后不遗留图标文件。
10. 完整前后端测试、前端构建、Docker 构建和隔离临时容器验证通过，且不影响 `/Docker/flymail/data` 中的现有邮件和账号数据。
