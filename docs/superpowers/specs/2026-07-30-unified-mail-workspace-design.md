# FlyMail 高密度统一邮件工作台设计

## 1. 目标

把 FlyMail 从“各页面分别定义布局和样式”的状态，重构为一套统一的高密度桌面邮件客户端界面。

本次设计同时解决视觉不统一和布局缺陷，重点包括：

- 页面滚动条消失、内容无法继续向下滚动。
- 页面内容只占上半部分或出现大块无意义空白。
- 主侧栏、二级导航栏和页面内容高度不一致。
- 有的页面贴边，有的页面有大间距，有的页面又包多层卡片。
- 页面分别声明 `height`、`padding`、`overflow`，造成样式冲突和难以预测的布局。
- 空状态、工具栏、页头、表格、卡片和分栏缺少统一模板。

视觉方向采用用户确认的 **高密度邮件客户端**：接近 Apple Mail、Outlook 等桌面工作台的信息密度，保持克制、稳定和清晰，不把所有页面做成宽松的大卡片后台。

## 2. 范围与边界

### 包含

- 应用壳、主侧栏、页面视口和移动抽屉。
- 全局高度与滚动模型。
- 页面布局组件和模板。
- 聚合收件箱、邮件管理、写邮件、联系人、同步管理、账号管理、邮件备份、用户管理、第三方通知、设置和关于页面。
- 深色、浅色和跟随系统主题。
- 桌面、平板和移动响应式布局。
- 视觉回归、滚动回归和 Docker 容器验证。

### 不包含

- 不修改邮件收发、同步、附件、定时发送和通知业务逻辑。
- 不修改认证方式、数据库表或数据隔离方式。
- 不修改 `/Docker/flymail/data` 与 `/data` 的持久化结构。
- 不新增生产依赖。
- 不上传 Docker Hub，除非用户明确要求。

## 3. 当前根因

### 3.1 滚动责任不明确

当前应用外壳使用固定视口高度并设置 `overflow: hidden`，但 `.main`、`.content` 和不同页面根元素之间没有统一的高度链路和滚动责任。

部分页面使用：

```css
height: 100%;
overflow-y: auto;
```

另一些页面使用：

```css
overflow: hidden;
```

还有页面没有明确滚动容器。结果是：

- 父元素截断内容，但子元素没有获得可计算高度。
- 页面超出视口后没有任何元素负责滚动。
- 空状态或分栏只按内容高度展开，下面留下大片背景。
- 同一页面可能同时出现两个纵向滚动容器。

### 3.2 兼容样式层覆盖页面私有样式

`page-system.css` 使用大量页面选择器和 `!important` 覆盖 scoped CSS。它修复了颜色，但没有真正统一结构，反而形成两套布局规则同时生效。

### 3.3 页面根节点缺少模板契约

当前所有页面虽然都包含 `.ui-page`，但 `.ui-page` 只统一颜色和部分间距，没有定义：

- 页面是否占满视口。
- 页头是否固定。
- 页面主体是否滚动。
- 分栏由谁滚动。
- 最大宽度是否存在。
- 空状态如何填满剩余空间。

## 4. 设计原则

### 4.1 一个页面只能有一个主滚动责任

- 普通管理页：页面主体滚动。
- 邮件工作台：各工作面板独立滚动，页面根不滚动。
- 左右分栏页：左栏和右栏独立滚动，页面根不滚动。
- 移动端：每个屏幕只保留一个主纵向滚动容器。

不允许页面根、主体和卡片同时声明纵向滚动，除非是明确的多面板工作台。

### 4.2 外壳始终稳定

- 主侧栏始终贯穿完整视口高度。
- 页面切换不改变侧栏高度、宽度、边界和底部账户位置。
- 主内容始终从侧栏右侧开始，占满剩余宽高。
- 页面内容多少不能影响应用壳尺寸。

### 4.3 高密度而不是拥挤

- 更小但稳定的控件高度。
- 更紧凑的页面内边距和卡片间距。
- 通过层级、分隔线和文字权重区分信息，不依赖大面积空白。
- 只在需要阅读的设置和说明页面使用最大内容宽度。

### 4.4 相同结构必须使用相同模板

页面不再自行决定整体布局。每个页面必须选择一个模板并遵守其高度、滚动、页头和内容规则。

### 4.5 动画服务于空间关系

- 侧栏和抽屉沿原路径进入和退出。
- 页面模板切换不做大幅移动。
- 按钮按下立即反馈。
- 支持减少动态、减少透明和高对比度偏好。

## 5. 全局应用壳

### 5.1 高度链路

以下元素形成完整高度链路：

```text
html
└── body
    └── #app
        └── .app-shell
            ├── .app-sidebar
            └── .main
                └── .content
                    └── 页面模板根节点
```

规则：

```css
html,
body,
#app {
  width: 100%;
  height: 100%;
  min-height: 0;
}

body {
  overflow: hidden;
}

.app-shell {
  width: 100%;
  height: 100dvh;
  min-height: 0;
  display: grid;
  overflow: hidden;
}

.main,
.content {
  min-width: 0;
  min-height: 0;
  height: 100%;
  overflow: hidden;
}
```

保留 `100vh` 作为不支持 `dvh` 的浏览器回退，但最终值优先使用 `100dvh`。

### 5.2 侧栏

- 展开宽度：248px。
- 折叠宽度：72px。
- 固定 72px 图标轨道。
- 顶部品牌区、导航区、底部账户区组成完整纵向布局。
- 只有中间导航区域允许滚动。
- 底部通知和账户区永远固定在侧栏底部。
- 侧栏不随页面内容高度变化。

### 5.3 页面视口

新增明确的页面视口层，负责：

- 挂载当前页面。
- 约束页面高度。
- 隐藏外层溢出。
- 为移动端导航触发器保留安全区域。

页面视口本身不提供通用滚动，滚动由具体模板负责。

## 6. 高密度尺寸规范

### 6.1 控件

| 类型 | 高度 |
| --- | ---: |
| 小图标按钮 | 32px |
| 常规按钮 | 36px |
| 主要按钮 | 38px |
| 输入框、下拉框 | 36px |
| 桌面工具栏 | 48px |
| 邮件列表行 | 48–52px |
| 普通表格行 | 44px |
| 移动端点击区域 | 最小 44px |

### 6.2 间距

采用 4px 栅格，常用值：4、8、12、16、20、24。

- 页面标准内边距：20px。
- 紧凑页面内边距：16px。
- 面板之间：12px。
- 面板内部：16px。
- 工具栏控件间距：8px。
- 表格和列表行横向内边距：12–16px。

不再使用随视口增长到 28px 的页面内边距，避免大屏出现过度留白。

### 6.3 圆角

- 输入框和按钮：8px。
- 小面板：10px。
- 主面板：12px。
- 弹窗和抽屉：14px。

工作台页面优先使用边界和分隔线，不为每个区域增加大圆角。

### 6.4 字体

- 页面标题：24px / 700。
- 区块标题：15–16px / 650。
- 常规正文：13–14px。
- 辅助信息：11–12px。
- 邮件列表主信息：13px / 550–600。
- 数字统计使用等宽数字特性。

## 7. 页面模板定义

## 7.1 Template A：Mail Workspace

用于高频、持续操作和多面板界面。

结构：

```text
WorkspacePage
├── Optional Secondary Navigation
└── WorkspaceMain
    ├── WorkspaceToolbar
    └── WorkspaceBody
        ├── List / Editor
        └── Optional Detail
```

规则：

- 根节点占满可用宽高并设置 `overflow: hidden`。
- 工具栏固定，不随列表滚动。
- 二级导航、列表和详情面板分别拥有自己的 `overflow-y: auto`。
- 面板之间使用 1px 分隔线，不使用外层大卡片。
- 列表为空时，空状态填满列表面板剩余区域。
- 使用 `scrollbar-gutter: stable`，避免数据加载后布局横向跳动。

适用页面：

- 邮件管理。
- 写邮件。
- 邮件备份。

### 邮件管理

- 主侧栏之后显示固定宽度二级邮件导航。
- 二级导航宽度：232px，大屏可为 240px，中等屏为 208px。
- 账号与文件夹共用同一滚动栏。
- 主工具栏固定在邮件列表顶部。
- 邮件列表独立滚动。
- 打开邮件详情时保持同一工作台高度，不创建新的页面高度。

### 写邮件

- 顶部操作栏固定。
- 收件人字段、主题、编辑器和附件位于一个可滚动编辑区。
- 编辑器内部不创建额外整页滚动。
- 联系人建议和签名面板作为浮层，不改变页面高度。

### 邮件备份

- 账号选择位于二级导航或紧凑横向栏。
- 归档列表和详情使用与邮件管理相同的列表/详情面板语言。
- 备份设置和状态作为工具栏下的紧凑信息条，不使用整页大卡片。

## 7.2 Template B：Collection / Management

用于列表、表格、统计和管理页面。

结构：

```text
CollectionPage
├── PageHeader
├── Optional Summary / FilterBar
└── ScrollBody
    ├── Panel / Table / Rows
    └── EmptyState
```

规则：

- 页面根节点占满宽高并设置 `overflow: hidden`。
- 页头和筛选栏固定在顶部。
- `ScrollBody` 是唯一纵向滚动容器。
- 内容默认使用全宽，不设置后台式窄最大宽度。
- 数据块优先使用紧凑行、表格和小面板，不堆叠巨大卡片。
- 空状态在内容面板内部填满可用高度。

适用页面：

- 聚合收件箱。
- 同步管理。
- 账号管理。
- 用户管理。

### 聚合收件箱

- 页头右侧保留选择邮箱、刷新和全部已读。
- 邮箱选择区域改为紧凑可展开面板或抽屉，不默认占据大面积高度。
- 筛选栏固定在消息列表上方。
- 消息列表占满剩余空间并独立滚动。
- 未选择邮箱或无邮件时，空状态填满消息面板。

### 同步管理

- 每个邮箱使用紧凑管理面板。
- 面板头部包含邮箱、服务商、状态和操作。
- 文件夹进度改为紧凑统计网格或表格。
- 状态卡片不使用过大的最小高度。
- 页面滚动由 `ScrollBody` 负责。

### 账号管理

- 页头、筛选和新增操作固定。
- 账号以紧凑列表或两列自适应卡片呈现。
- 对话框继续浮于页面之上。
- 删除或同步任务状态以行内状态条展示。

### 用户管理

- 筛选区固定。
- 表头可粘性定位。
- 表格容器独立滚动。
- 小屏改为紧凑卡片列表，但仍保持单一滚动容器。

## 7.3 Template C：Split View

用于目录列表加详情内容。

结构：

```text
SplitPage
├── SplitListPane
│   ├── PaneToolbar
│   └── PaneScrollBody
└── SplitDetailPane
    ├── DetailToolbar
    └── DetailScrollBody / EmptyState
```

规则：

- 根节点使用 `grid`，占满宽高并 `overflow: hidden`。
- 左栏宽度桌面 320px，中等屏 280px。
- 左右面板都必须伸展到完整可用高度。
- 左列表和右详情分别滚动。
- 右侧无选择时，空状态填满整个详情面板。
- 页面不得只按内容高度展开。

适用页面：

- 联系人。

### 联系人

- 左侧包含搜索、新增和联系人列表。
- 右侧显示联系人详情、编辑状态或空状态。
- 删除、编辑和保存动作固定在详情工具栏。
- 移动端一次只显示列表或详情，返回按钮保持固定。

## 7.4 Template D：Settings Document

用于设置、说明和低频配置。

结构：

```text
DocumentPage
├── PageHeader
└── DocumentScrollBody
    └── DocumentColumn
        ├── SectionPanel
        └── SectionPanel
```

规则：

- 页面主体是唯一滚动容器。
- 内容列最大宽度：960px。
- 内容列在宽屏居中，但页头与内容列对齐。
- 分组面板保持紧凑，不使用超大内边距。
- 表单标签、帮助文字、错误状态和按钮位置统一。

适用页面：

- 设置。
- 第三方通知。
- 关于。

## 8. 公共布局组件

新增或重构以下公共组件：

### PageFrame

Props：

- `variant`: `workspace | collection | split | document`
- `density`: 默认 `compact`
- `edge`: 是否取消外层内边距

职责：

- 占满页面视口。
- 应用模板基础高度和滚动规则。
- 不处理业务数据。

### PageHeader

统一：

- 标题和副标题。
- 右侧操作区。
- 小屏换行行为。
- 固定高度与下边界。

### PageToolbar

统一：

- 48px 高度。
- 搜索、筛选、批量操作和主要操作布局。
- 滚动边缘材质和 sticky 行为。

### UiPanel

用于结构面板而不是装饰性卡片：

- 统一背景、边框和圆角。
- `flush` 模式允许列表直接贴合面板边缘。
- 可选 header、body、footer。

### UiScrollRegion

统一滚动行为：

- `min-height: 0`。
- `overflow: auto`。
- `overscroll-behavior: contain`。
- `scrollbar-gutter: stable`。
- 键盘可达。

### UiEmptyState

统一：

- 图标、标题、说明和可选操作。
- 默认填满父容器。
- 不依赖固定像素 `min-height`。

### UiDataRow / UiTableShell

统一管理页和列表页的行高、hover、selected、focus 和分隔线。

## 9. 样式组织

### 保留

- `tokens.css`：语义颜色、尺寸、字体和动画 token。
- `base.css`：根元素、可访问性和浏览器基础样式。
- `components.css`：按钮、输入框、浮层等通用控件。
- `app-shell.css`：应用壳和侧栏。

### 重构

- 将 `page-system.css` 从“按具体页面覆盖”改为“按模板和公共布局组件定义”。
- 页面 scoped CSS 只保留业务内部结构，不再声明页面根高度、全局内边距和主滚动规则。
- 移除用于修补页面颜色和布局的大量 `!important`。
- 兼容旧 class 的规则只在迁移期间保留，最终不承担页面骨架职责。

### 禁止

业务页面不得自行声明以下属性，除非是模板内部明确的子面板：

```text
height: 100vh
height: 100%
overflow-y: auto
overflow: hidden
页面级 padding
页面级 max-width
```

这些属性由 PageFrame 和模板负责。

## 11. 滚动与布局验收标准

### 全局

- 主侧栏始终从顶部延伸到底部。
- 页面切换时主内容区域尺寸不跳动。
- 应用 body 不出现主滚动条。
- 页面内容不会被 `overflow: hidden` 截断。

### 普通页面

- 内容超出时可使用鼠标滚轮、触控板、PageDown 和键盘滚动。
- 滚动条出现在页面主体而不是整个浏览器窗口。
- 页面内容不足时面板仍填满可用高度，不出现“只占半页”。

### 工作台页面

- 二级导航、邮件列表和详情分别独立滚动。
- 工具栏和列表头保持可见。
- 滚动一个面板不带动其他面板。
- 面板内容加载前后宽度不跳动。

### 分栏页面

- 左右栏等高并填满视口。
- 空详情状态占满右栏。
- 左栏长列表和右栏长详情都可独立滚动。

## 12. 响应式规则

### ≥ 1440px

- 展开主侧栏 248px。
- 工作台二级栏 232–240px。
- 管理页面使用完整宽度。

### 1024–1439px

- 主侧栏保持 248px 或用户折叠的 72px。
- 工作台二级栏缩小至 208–220px。
- 工具栏可以隐藏次要文字标签，但不改变主要功能位置。

### ≤ 960px

- 主侧栏改为抽屉。
- 页面占满宽度。
- 管理页页头允许两行。
- 工作台二级栏通过抽屉或切换面板呈现。

### ≤ 768px

- Split View 一次显示一个面板。
- 表格转为卡片列表。
- 工具栏允许横向滚动或收纳次要操作。
- 不允许页面横向溢出。

## 13. 动画规范

- 侧栏宽度：200–240ms，连续且可反向操作。
- 抽屉：220ms，无无意义弹跳。
- Popover：160–180ms，从触发器方向出现。
- 页面内容切换：不使用整页滑动，只允许短淡入。
- 按钮按压：80–100ms，轻微缩放。
- 只动画 `transform`、`opacity` 和必要的侧栏宽度。
- 减少动态模式下改为短淡入或无动画。
