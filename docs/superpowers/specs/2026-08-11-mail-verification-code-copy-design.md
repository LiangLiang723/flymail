# 邮件验证码识别与一键复制设计

## 目标

在 FlyMail 邮件列表中本地识别主题或已缓存正文里的验证码；识别成功时，在主题区域与已读/未读状态之间显示“复制验证码”按钮，点击后仅复制验证码而不打开邮件。

## 方案选择

调研的开源实现主要有三类：

1. 仅使用固定长度正则抓取数字；实现简单，但容易把日期、订单号、电话号码、发票号识别成验证码。
2. 使用上下文关键词、候选码长度和负面语义共同评分；适合邮件 Subject/Text/HTML，且无需模型或外部服务。
3. 绑定 IMAP 轮询的完整 OTP 接收器；功能更重，会与 FlyMail 现有 IMAP 同步职责重复。

FlyMail 采用第 2 类思路：后端 Python 标准库实现上下文感知解析，不增加生产依赖，不向第三方发送邮件内容，也不重复实现 IMAP 连接。

## 识别规则

- 输入优先级：主题 > 纯文本正文 > HTML 转文本。
- 第一版验证码为 4–8 位数字；支持连续数字以及常见空格/短横线分组形式，返回时移除分隔符。
- 正向上下文覆盖中文验证码、验证代码、验证身份、校验码、动态码、动态密码、一次性密码、安全码、认证码、登录码、确认码，以及英文 OTP、verification code、security code、authentication code、login code、confirmation code、passcode、PIN、one-time code/password 等。
- 候选码必须靠近正向上下文；越近优先级越高。
- 订单、发票、物流、电话、金额、优惠券、邀请码、日期等负向上下文降低或取消候选优先级。
- 明显日期片段和嵌在更长数字串中的片段不作为验证码。
- 不持久化验证码，不写日志；每次列表响应仅基于主题和当前已经缓存的正文动态计算。
- 正文尚未缓存时只依据主题识别；正文后续进入缓存后，下一次列表刷新即可识别正文验证码。

## 后端数据流

`backend/services/verification_code.py` 提供纯函数 `extract_verification_code(subject, body_text, body_html) -> str`。

邮件列表首先直接从返回项主题识别。对于主题未命中的当前页邮件，后端用一条按 `user_uid + account_id + folder + uid IN (...)` 约束的 MySQL 查询读取有限长度的正文片段，再进行正文识别。这样不会把完整正文塞进列表 API，也不会为每封邮件执行单独查询。

远端列表临时回退路径通过 `_message_to_item()` 对远端对象已有的主题/正文执行同一解析器；详情 API 保持原有正文行为。

不增加数据库列，不迁移历史数据，不修改 `/data` 目录结构。

## 前端交互

- `Message` / `MessageItem` 增加可选 `verification_code` 字段。
- `MailList.vue` 在邮件主题区域后、已读/未读标签前插入固定动作按钮。
- 按钮文案为“复制验证码”；通过 `aria-label` 提供包含验证码值的明确可访问名称。
- 点击按钮必须 `stopPropagation`，只复制验证码，不打开邮件、不进入多选。
- 邮件行外层改为可聚焦的 `div role="button"`，保留点击、Enter、Space、右键多选能力，从而避免在 `<button>` 中嵌套另一个 `<button>` 的无效交互结构。
- 复制优先使用 `navigator.clipboard.writeText()`，不支持或失败时使用临时 textarea + `document.execCommand('copy')` 兜底；成功只提示“验证码已复制”，不在 toast 再次显示敏感值。
- 按钮为固定动作，`flex-shrink: 0`；主题继续 `min-width: 0` + ellipsis。移动端按钮进入第二行主题轨道，不制造页面级横向滚动。

## 能力边界

- 这是确定性启发式识别，不存在对所有邮件模板都“完美”的通用解析器。
- 第一版只识别 4–8 位数字验证码；字母数字混合码不主动猜测，优先降低误报。
- 只有已进入 FlyMail 缓存的正文才能参与列表识别；主题始终可以立即识别。
- 验证码不会自动填入第三方网站，只提供一键复制。

## 验收

1. `24681357 是您的验证码` 与 Atlassian 风格模板 `24681357 是您的验证代码` 都能从主题识别为 `24681357`；正文只有“需要验证自己的身份 / 请输入以下代码：24681357”时也能识别。
2. `您的验证码是 123-456` 返回 `123456`。
3. 只有正文出现 `Your verification code is 654321` 时可识别。
4. HTML 正文中的验证码可识别。
5. 订单号、日期、电话、发票号在没有可靠验证码上下文时不显示按钮。
6. 同一段文本包含订单号和验证码时选择离验证码语义最近的真实验证码。
7. 列表 API 不返回为识别而读取的正文片段，只新增 `verification_code`。
8. 点击“复制验证码”不会触发邮件打开；桌面和 390×844 移动端无新增横向溢出。
9. 不新增第三方生产依赖，不修改数据库 schema，不影响 `/Docker/flymail/data`。
