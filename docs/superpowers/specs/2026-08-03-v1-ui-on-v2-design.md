# FlyMail V2 保留功能并恢复 V1 全量 UI 设计

## 目标

保留 V2 的 FastAPI、Worker、MySQL schema、路由、认证、线程、搜索、同步、写信、通知、备份和实时事件能力，只恢复 V1 的完整视觉语言与应用壳层。

## 方案选择

采用“V2 功能内核 + V1 展示层”方案：正式入口仍是 `AppV2.vue`，不切回依赖旧 API 的 `App.vue`。V2 页面继续调用 `/api/v2`，通过 V1 的设计 token、公共样式、侧栏结构和兼容样式统一外观。

不采用以下方案：

- 直接切回 `App.vue`：会回退到旧 API 和旧状态模型，破坏 V2 功能。
- 只修改三份 V2 CSS 的颜色：无法恢复 V1 的全局侧栏、页面层级、登录页和非邮件页面布局。

## 应用壳层

- 登录后恢复 V1 的 248px 展开、72px 折叠固定侧栏。
- 侧栏恢复 FlyMail Logo、主导航、通知、用户菜单、版本号和移动抽屉。
- 邮件路由在主内容区内保留 V2 的账号/文件夹、会话列表、会话详情三栏。
- 设置、资料、账号、联系人、同步、通知、管理员、备份、关于、搜索和写信路由使用单内容工作区，不再强制套入邮件三栏。

## 视觉系统

- 正式入口加载 V1 的 `tokens.css`、`base.css`、`components.css`、`app-shell.css`、`layout-system.css`、`page-system.css`。
- V2 token 映射到 V1 语义 token，恢复紫色强调色、Apple 风格系统字体、细边框、紧凑圆角和克制阴影。
- 新增 V2 到 V1 的兼容样式，覆盖 V2 线程、正文、附件、搜索、写信、账号、同步、通知、管理员和备份页面。
- 深浅主题继续由 V2 偏好控制，但实际颜色取 V1 token。

## 登录页

登录行为继续使用 V2 服务端会话和 CSRF 流程；展示恢复 V1 的 Logo、欢迎文案、卡片、字段、错误提示和主按钮。

## 数据与安全边界

- 不修改后端、数据库 schema、Worker、对象存储或环境变量。
- 不读写或迁移 `/Docker/flymail/data` 内容。
- 临时容器使用独立临时目录；验证通过后仅以同一 `/Docker/flymail/data:/data` 挂载重建正式容器。
- 不新增生产依赖。

## 验收标准

1. 所有正式 V2 路由和 API 行为保留。
2. 登录页、全局侧栏、移动抽屉、邮件三栏和全部功能页恢复 V1 设计语言。
3. 非邮件页面使用独立主工作区，不显示无意义的空邮件详情栏。
4. 桌面、平板、移动断点仍可用，键盘焦点与减少动态偏好保留。
5. V2 前端测试、兼容前端测试、类型检查和生产构建通过。
6. 后端测试、Shell、Compose、镜像、临时容器健康、MySQL 8.0、持久化重启与秘密检查通过。
