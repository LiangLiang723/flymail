# 签名图片缩放与写信光标修复设计

日期：2026-08-06
目标版本：0.0.37

## 背景

当前签名编辑器已支持上传本地图片，但图片节点只保存 `src`，用户无法调整并持久化显示尺寸。

写信页应用默认签名后只负责插入或替换 `signatureBlock`，没有建立稳定的正文输入区和选区位置。用户开始输入时，文字可能进入受 FlyMail 管理的签名块；之后切换邮箱或签名时，旧签名块被整体删除，导致签名前几行正文一并消失。

## 目标

1. 签名图片可以调整大小，尺寸随签名 HTML 保存并在发送邮件时保持。
2. 新建邮件自动应用签名后，光标位于正文最顶部。
3. 正文输入区与签名之间始终保留一个空白段落。
4. 回复和转发中，签名位于新正文与原邮件引用之间。
5. 替换或删除签名时，只删除 FlyMail 管理的签名节点，绝不删除用户正文。
6. 草稿正文和已有签名保持原样，不自动重排或覆盖。

## 非目标

- 不改变签名图片上传接口、存储目录或图片公开访问规则。
- 不实现图片裁剪、旋转、压缩质量选择或自由宽高变形。
- 不迁移数据库，也不删除现有签名图片。
- 不尝试重写整个 Tiptap 编辑器。

## 图片尺寸设计

### 数据模型

扩展当前 Tiptap `Image` 节点，新增可选 `width` 属性：

- HTML 解析时读取 `width` 属性或内联 `style="width: ..."`。
- HTML 输出时写入像素宽度，例如 `<img src="..." width="320">`。
- 高度保持自动，避免图片变形。
- 未设置宽度的历史图片继续使用 `max-width: 100%`，兼容已有签名。

允许宽度范围：

- 最小 80px。
- 最大不超过编辑区可用宽度。
- 拖拽结束后保存整数像素值。

### 桌面端交互

点击图片后：

- 显示选中边框。
- 右下角显示拖拽手柄。
- 拖动手柄按原始宽高比改变宽度。
- 拖动过程中实时预览。
- 松开后通过 Tiptap transaction 写回节点 `width`，触发 `v-model` 更新。

点击编辑器其他位置、按 `Escape` 或删除图片后取消选中。

### 移动端交互

移动端不依赖精细拖拽，选中图片时显示四个快捷尺寸：

- 25%
- 50%
- 75%
- 100%

百分比基于当前编辑器可用宽度换算成像素，并写回同一个 `width` 属性。桌面端也可显示该快捷栏，作为可访问的替代操作。

### 可访问性

- 图片选中工具栏使用明确按钮文字。
- 拖拽手柄提供 `aria-label="调整图片大小"`。
- 快捷尺寸按钮具备可见焦点状态。
- 键盘用户可通过快捷尺寸完成全部必要操作。

## 写信正文与签名结构

### 新建邮件

应用签名后的文档结构固定为：

```html
<p><br></p>
<p><br></p>
<div data-flymail-signature="SIGNATURE_ID">...</div>
```

含义：

1. 第一段是正文输入段，光标放在该段开头。
2. 第二段是正文与签名之间的空白分隔段。
3. 第三部分是只由 FlyMail 管理的签名块。

若用户已经输入正文，再切换签名时，不新增重复空行，只替换签名块并保留全部正文。

### 回复与转发

结构固定为：

```html
<p><br></p>
<p><br></p>
<div data-flymail-signature="SIGNATURE_ID">...</div>
<blockquote data-flymail-quote="...">...</blockquote>
```

实际实现不依赖引用节点必须是 `blockquote`，而是将签名插入到原邮件引用之前；正文输入段和分隔段位于最顶部。

### 草稿

草稿加载时不调用结构规范化：

- 保留已保存 HTML。
- 保留已有光标以外的内容顺序。
- 不自动应用默认签名。

### 切换签名

`setManagedSignature` 的职责改为：

1. 找到并删除现有 `signatureBlock` 节点。
2. 保留签名块之外的所有节点。
3. 确保目标位置前存在正文输入段和一个分隔段。
4. 插入新的签名块。
5. 将光标移动到最顶部正文段开头。

当选择“无签名”时：

- 只删除签名块。
- 不删除正文。
- 不强制保留多余分隔段；可删除仅由签名结构创建且仍为空的分隔段。
- 光标仍回到正文顶部。

## 防止正文随签名消失

根因修复原则：用户可输入区域不能位于 `signatureBlock` 内。

措施：

- `signatureBlock` 保持 `isolating: true`。
- 插入签名后显式设置 TextSelection 到首个正文段。
- 不使用当前选区决定签名插入位置。
- 替换签名只按节点类型删除，不按 HTML 字符串或相邻段落范围删除。
- 添加回归测试：在签名前输入多段文字后切换签名，正文逐字保持不变。

## 组件边界

### `frontend/src/components/TiptapEditor.vue`

负责：

- 可调整尺寸的图片节点。
- 图片选中状态、拖拽手柄和快捷尺寸。
- 签名文档结构规范化。
- 签名插入、替换、删除后的光标定位。

对父组件继续暴露 `setManagedSignature`，不新增写信页对 ProseMirror 内部状态的依赖。

### `frontend/src/views/ComposeEmail.vue`

负责：

- 根据新建、回复、转发场景选择签名放置模式。
- 草稿不自动应用默认签名。
- 切换签名时调用编辑器公共接口。

不直接拼接编辑器 HTML，不操作 Tiptap selection。

## 错误与边界处理

- 图片自然宽度未加载时，使用当前渲染宽度作为拖拽基准。
- 编辑器宽度小于 80px 时，以编辑器实际宽度为上限。
- 历史 HTML 中非法、负数或超大宽度在解析后限制到安全范围。
- 图片加载失败不影响签名正文编辑，仍可选中并删除。
- 空签名保持现有提示，不插入空 `signatureBlock`。

## 测试策略

### 单元与契约测试

1. 图片节点可以解析和输出 `width`。
2. 图片宽度限制在 80px 到编辑区宽度之间。
3. 快捷尺寸正确换算并写回宽度。
4. 新建邮件签名结构包含正文段、分隔段和签名块。
5. 应用签名后 selection 位于首个正文段。
6. 切换签名后，签名前多段正文完全保留。
7. 选择无签名后正文仍保留。
8. 回复和转发的签名位于引用内容之前。
9. 草稿加载不自动重排签名。

### 浏览器回归

1. 上传图片后点击图片，拖动手柄改变尺寸。
2. 保存签名、重新进入编辑，尺寸保持。
3. 390px 移动视口使用 25% / 50% / 75% / 100% 快捷按钮。
4. 新建邮件应用默认签名后，输入文字出现在签名上方并有一行间隔。
5. 连续输入多行，再切换签名和发件邮箱，文字不消失。
6. 回复和转发中输入区、签名、原邮件引用顺序正确。

## 发布与数据影响

- 目标版本：`0.0.37`。

- 不修改数据库结构。
- 不迁移或删除 `/Docker/flymail/data`。

- 修改前端应用后需要重建镜像并替换当前 `flymail` 容器。
