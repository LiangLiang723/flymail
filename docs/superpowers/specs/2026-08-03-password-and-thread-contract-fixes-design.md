# FlyMail 密码限制与线程列表契约修复设计

日期：2026-08-03

状态：用户已确认

## 1. 背景

生产 `0.1.2` 暴露两个独立问题：

1. 空数据库首次管理员密码被限制为至少 12 个字符，且用户创建、改密、管理员重置、邮箱凭据、代理密码和备份密码在前后端存在不同的最短或最大长度限制。
2. `/api/v2/threads` 后端按冻结 OpenAPI 返回 `{ items, next_cursor }`，前端手工维护的 TypeScript 类型和缓存逻辑却读取 `{ threads, next_cursor }`，空邮箱登录后执行 `response.threads.map(...)`，触发 `Cannot read properties of undefined (reading 'map')`。

## 2. 密码规则

所有由用户输入并作为密码、授权码或备份口令使用的字符串统一采用以下规则：

- 必须非空。
- 不设置应用层最短长度。
- 不设置应用层最大长度。
- 不自动去除首尾空格，哈希、加密和验证必须使用用户输入的原始值。
- 邮箱服务商、MySQL、HTTP 服务器或浏览器自身仍可能施加协议或产品限制；FlyMail 不额外增加长度限制。

覆盖范围：

- 空数据库首次管理员密码。
- 登录密码。
- 用户修改密码。
- 管理员创建用户和重置密码。
- 邮箱密码、授权码和账号凭据。
- HTTP CONNECT 代理密码。
- 业务备份密码。
- 仍保留在仓库中的旧认证路由，避免未来重新启用时出现不同规则。

不属于用户密码的安全密钥不放宽：

- `FLYMAIL_SESSION_SECRET` 继续至少 16 个字符，因为它用于会话签名并派生邮箱、代理和通知凭据的实例加密密钥。
- 游标签名密钥、凭据主密钥和其他内部密钥继续保持现有安全要求。
- `MYSQL_PASSWORD` 继续要求非空且禁止换行；不新增长度限制。

## 3. 线程列表契约

后端 OpenAPI 和实际响应是事实来源，保持 `/api/v2/threads` 返回：

```json
{
  "items": [],
  "next_cursor": null
}
```

前端增加明确的 API 原始类型 `ThreadListItemResponse`，字段与后端 `ThreadListItem` 一致。前端使用一个纯函数把原始条目转换成现有列表视图模型 `ThreadProjection`：

- `latest_message_at` → `latest_at`
- `latest_snippet` → `snippet`
- `pending_operation_count > 0` → `pending_state = "pending"`
- 其余列表字段按名称复制

`ThreadCursorMemory` 只缓存已经归一化的视图模型，分页追加、实时补丁和 UI 组件继续使用同一内部结构。空数组必须正常渲染空列表，不允许通过可选链掩盖错误契约。

## 4. 错误处理与安全

- 空密码统一由请求 schema 或业务入口返回 422/配置错误。
- 密码不得出现在响应、日志、测试失败输出或 Git 差异中。
- 放宽长度不会改变密码哈希算法、凭据加密、CSRF、会话撤销或多用户隔离。
- 线程响应字段缺失时应在归一化边界产生可定位错误，而不是在 Vue 渲染阶段出现模糊的 `undefined.map`。

## 5. 测试与发布

先写失败测试，再做最小实现：

- 首次管理员可使用单字符密码，空密码仍失败。
- 创建用户、用户改密和管理员重置可使用单字符密码，随后可登录。
- 备份 schema 与备份创建接受单字符密码，空密码仍失败。
- 邮箱凭据和代理密码 schema 接受超长字符串。
- 前端静态合同不再包含 12 位提示或按钮长度判断。
- `ThreadCursorMemory` 接收真实 `{ items, next_cursor }` 响应，空列表和分页均不抛异常。
- 运行完整后端、前端、构建、Compose、镜像、隔离容器和秘密扫描。
- 发布补丁版本 `0.1.3`，仅替换生产容器镜像并保留 `/Docker/flymail/data`。
