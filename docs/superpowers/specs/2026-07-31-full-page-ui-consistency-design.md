# FlyMail 全页面 UI 一致性设计

## 目标

把账号管理、联系人以及其余一级页面收口到同一套页面框架和视觉语言，避免页面虽然使用相同主题色，却仍在工具栏、内容宽度、面板边界、圆角和空状态上各自实现。

## 根因

当前一级页面已经接入 `PageFrame`，但公共模板只统一了外层间距和滚动归属：

- `PageFrame` 的 toolbar 插槽仍渲染为横跨页面的直角条，账号管理和用户管理因此与其他卡片式页面不一致。
- split 模板只提供外边距，没有提供统一面板表面，联系人左右栏看起来像直接铺在画布上。
- management 页面没有统一最大内容宽度，超宽屏下账号卡片被拉得过长。
- 多个页面继续维护自己的空状态 DOM 和样式，图标、间距、字号和表面表现不同。

## 设计原则

1. 页面按用途分为 workspace、management、split、document 四种模板，不强制所有页面采用同一信息结构。
2. 同一模板必须共享内容宽度、页头对齐、工具栏表面、面板边界、圆角和阴影。
3. 空数据状态统一复用 `UiEmptyState`，加载状态统一复用 `UiLoadingState`，页面只提供文案、图标和紧凑/面板表现参数。
4. 桌面端 management 页面内容最大宽度为 1280px，document 页面保持 960px；窄屏自动铺满。
5. split 页面桌面端使用完整圆角面板，移动端恢复边到边布局。
6. 不修改业务接口、数据结构、权限、邮箱行为和 `/data` 持久化。

## 页面模板

### Management

页头、可选工具栏和内容栈共享 1280px 对齐线。工具栏是带边框、圆角和阴影的独立面板，不再使用全宽底边条。

适用：聚合收件箱、同步管理、账号管理、用户管理。

### Split

页面正文形成一个完整面板，负责外层边框、圆角、阴影和裁切；左右栏只负责内部表面和分隔线。

适用：联系人。

### Workspace

保留邮件、写信和备份的高密度工作区结构，继续由各自内部容器管理工具栏和滚动，但使用公共边框、圆角和阴影。

### Document

页头与 960px 文档列对齐，卡片采用统一表面和纵向节奏。

适用：设置、第三方通知、关于、个人资料。

## 加载与空状态

扩展 `UiEmptyState` 支持 `compact` 和 `panel` 两个表现参数，并新增同样支持这两个参数的 `UiLoadingState`：

- `compact` 用于联系人左栏、备份列表等狭窄区域。
- `panel` 用于管理页和文档页内容区域，提供统一边框、圆角、背景和阴影。
- `UiLoadingState` 使用统一旋转指示器，并在系统启用“减少动态效果”时停止动画。

账号管理、联系人、同步管理、聚合收件箱和备份的空状态改用 `UiEmptyState`；账号管理、联系人、同步管理、聚合收件箱、备份和第三方通知的加载状态改用 `UiLoadingState`。

## 验收标准

- 账号管理工具栏不再横跨整页，账号列表在超宽屏不会无限拉伸。
- 联系人页面桌面端拥有清晰的完整圆角外框，左右面板边界明确。
- 所有 management 页的页头、工具栏和正文使用同一最大宽度与水平起始线。
- 所有一级页面不再自行覆盖模板负责的根节点外边距。
- 主要空状态复用 `UiEmptyState`，主要加载状态复用 `UiLoadingState`，图标、指示器、标题、描述和表面一致。
- 现有前端测试、类型检查、构建、后端测试和 Docker 容器验证全部通过。
