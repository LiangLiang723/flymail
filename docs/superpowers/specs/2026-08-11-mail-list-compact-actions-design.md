# FlyMail 邮件列表紧凑操作与层级精修设计

## 1. 目标

在现有 `0.0.51` 邮件列表视觉层级基础上继续做一轮局部精修，只调整用户已经确认的四项：

1. 验证码复制操作改成始终可见的纯图标按钮。
2. 桌面端发件人列收窄，给主题释放更多可用宽度。
3. 当前文件夹标题增强层级，让“我现在在哪个文件夹”更清楚。
4. 继续弱化邮件列表的表格感，以更淡的分隔线和更自然的 hover 建立行边界。

本轮不改变邮件主题内容、不做验证码数字结构化、不改搜索位置、不改业务接口和数据结构。

## 2. 已确认约束

- 搜索继续保持在当前桌面工具栏右侧这一行。
- 验证码复制按钮必须始终显示，只保留复制图标，不显示“复制”或“复制验证码”文字。
- 复制图标仍必须可点击，点击不能打开邮件详情。
- 复制操作继续保留可访问名称和提示，不能因为去掉文字而失去键盘/读屏可用性。
- 发件人列只在桌面端收窄；移动端继续使用现有自适应布局。
- 当前文件夹标题只增强文字层级，不增加新行、不增加大标题区。
- 邮件列表继续保留未读点、未读字重、附件图标、未读徽标、验证码复制、日期和分页。
- 不修改验证码识别逻辑、会话逻辑、搜索/筛选、WebSocket、同步、分页、附件和邮件详情。
- 不修改后端接口、数据库、环境变量或 `/Docker/flymail/data`。

## 3. 当前实现基线

当前 `MailList.vue` 已具备以下状态：

- `.list-count` 只显示 `mailStore.currentFolderName`。
- 验证码邮件在主题右侧渲染 `.verification-code-copy`，当前内容为“复制验证码”文字。
- `.mail-sender` 在最终桌面样式覆盖中宽度为 `190px`。
- 邮件行最终覆盖样式的分隔线为 `color-mix(in srgb, var(--border-color) 58%, transparent)`。
- hover 使用 `var(--bg-hover)`。
- 768px 以下移动端 `.mail-sender` 为自适应宽度，验证码按钮进入 `code` grid area。

因此本轮可以在现有组件内做小范围模板与 CSS 调整，不需要新组件或新依赖。

## 4. 方案选择

### 方案 A：现有组件内做紧凑视觉调整（采用）

- 在现有 `.verification-code-copy` 中放一个复制 SVG 图标。
- 保留原 `aria-label`，补充 `title="复制验证码"`。
- 桌面端按钮固定为紧凑方形点击区域。
- `.mail-sender` 从 `190px` 收窄到固定 `165px`。
- `.list-count` 提升为次级标题层级。
- 分隔线强度固定降到 `36%`，并让 hover 成为更主要的行反馈。

优点：改动小、语义清楚、与当前实现连续，不会引入新的状态管理。

### 方案 B：抽成通用 `UiIconButton`

把验证码操作改为现有通用图标按钮组件。

优点：组件复用更统一。缺点：当前邮件行对按钮尺寸、grid area 和视觉密度有专用需求，引入通用组件反而需要额外覆盖样式。本轮目标是局部精修，不采用。

### 方案 C：只用 CSS 隐藏文字并用伪元素画图标

优点：模板改动最少。缺点：图标语义和可维护性较差，伪元素不适合承载交互图形，也不利于可访问性测试，不采用。

## 5. 具体设计

### 5.1 验证码复制图标

模板保持原按钮结构和点击逻辑：

```vue
<button
  v-if="msg.verification_code && !selectMode"
  class="verification-code-copy"
  type="button"
  :aria-label="`复制验证码 ${msg.verification_code}`"
  title="复制验证码"
  @click.stop="copyVerificationCode(msg.verification_code)"
>
  <svg ... aria-hidden="true">...</svg>
</button>
```

图标采用常见的“双矩形叠放”复制符号，线条风格与当前 FlyMail 工具栏 SVG 保持一致：`fill="none"`、`stroke="currentColor"`、圆角线帽/连接。

视觉要求：

- 桌面始终可见。
- 不显示任何文字。
- 点击区域保持至少约 `28×28px`，图标本身约 `14–16px`。
- 默认颜色使用三级或次级文字色，避免成为列表主要视觉焦点。
- hover 时提高到强调色，并提供轻微 hover 背景。
- focus-visible 保留清晰焦点环。
- 日期仍然是最右列，复制图标位于日期左侧。
- `@click.stop` 保持不变，点击图标不打开邮件。

移动端同样只显示图标，不恢复文字；按钮放在现有 `code` grid area，尺寸收敛为紧凑方形，不占用原先 72px 的文字按钮宽度。

## 6. 发件人列

最终桌面样式中的：

```css
.mail-sender {
  width: 190px;
}
```

改为固定 `165px`。

同时小幅收紧头像与发件人间距、右侧 padding，但不改变头像尺寸和省略号规则。

设计目标：

- 释放约 20–30px 给主题。
- 常见的 `Atlassian`、`Microsoft`、个人姓名仍然完整显示。
- 长发件人继续通过 `text-overflow: ellipsis` 截断。
- 1180px 以下现有 `150px` 响应式规则保持，不继续压缩。
- 移动端保持自适应，不使用固定 165px。

## 7. 当前文件夹标题

`.list-count` 从“弱提示文字”提升到“工作区上下文标题”，但仍保持紧凑单行。

建议最终属性：

- 字号固定为 `13px`。
- 颜色从 `var(--text-tertiary)` 提升为 `var(--text-primary)`。
- 字重从 medium 提升到 `var(--font-semibold)`。
- 不增加额外背景、边框或图标。
- 不显示未读数/全部数，避免恢复上一轮已经移除的重复信息。

这样“验证码 / 收件箱 / 已发送”等当前位置会明显高于后面的快速筛选，但不会成为大标题。

## 8. 继续降低表格感

邮件行不取消分隔线，只继续降低静态边界权重：

- 最终覆盖区的 `border-bottom-color` 从当前 58% 固定降低到 `36%`。
- hover 背景保持轻量，但相对静态边界更容易感知。
- selected 继续使用现有 `var(--bg-active)`，不改语义。
- 未读状态点继续保留，作为未读扫描锚点。
- 行高不做明显增加；如需要只允许 1px 级微调，避免减少首屏邮件数量。

目标是：静止时列表更像连续邮件流，鼠标经过时才形成清晰的当前行边界。

## 9. 可访问性

- 纯图标复制按钮必须保留动态 `aria-label="复制验证码 <code>"`。
- SVG 使用 `aria-hidden="true"`，避免读屏重复读取图形。
- 按钮保留 `title="复制验证码"` 作为鼠标提示。
- focus-visible 必须清晰可见。
- 按钮仍然是原生 `button`，保持键盘激活能力。
- 复制图标不能只通过 hover 才出现；用户已明确要求始终显示。

## 10. 测试契约

新增或调整前端契约测试，至少锁定：

1. `.verification-code-copy` 内存在 SVG 复制图标且不包含“复制验证码”可见文字。
2. 按钮继续保留动态 `aria-label`、`title` 和 `@click.stop`。
3. 桌面 `.verification-code-copy` 是紧凑方形按钮，不再拥有 `min-width: 78px`。
4. 移动端 `.verification-code-copy` 同样是紧凑图标尺寸，不再拥有 `min-width: 72px`。
5. 最终桌面 `.mail-sender` 宽度为 `165px`；1180px 以下现有 `150px` 规则仍存在。
6. `.list-count` 使用更高文字层级和 semibold 字重。
7. 邮件行最终分隔线强度低于当前 58%。
8. 搜索仍位于 `toolbar-right`，桌面仍 `flex-wrap: nowrap`。
9. 移动端列表仍 `overflow-x: hidden`，不引入横向溢出。

## 11. 浏览器验收

使用实际生产构建产物验证：

- 1440×900：复制图标始终显示，发件人列明显更紧凑，主题获得更多空间，文件夹标题层级更清楚。
- 1920×1080：同上，并确认列表没有因为宽屏出现不必要的空白错位。
- 390×844：复制图标仍是纯图标，列表无页面级横向溢出。
- 200% 等价场景：工具栏和邮件行不重叠，复制按钮和日期仍可访问。
