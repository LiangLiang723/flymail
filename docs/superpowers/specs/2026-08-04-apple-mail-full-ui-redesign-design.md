# FlyMail Apple Mail 风格整站 UI 重设计

## 1. 目标

把 FlyMail 的登录页、应用壳层、邮件工作台、写信、联系人、聚合收件箱、账号管理、同步管理、备份、设置、个人资料、第三方通知、用户管理、关于页和全局浮层统一为一套 Apple Mail 风格、紧凑高效、系统蓝主色的产品界面。

本次不是局部换肤。核心交付是：

1. 桌面邮件页变为真正同时可见的三栏工作台。
2. 全部一级页面共享同一视觉语言和页面骨架。
3. 浅色、深色、移动端、键盘和低动态偏好保持可用。
4. 保留现有 Vue、Pinia、FastAPI、接口和业务逻辑。

## 2. 已确认方向

- 风格：Apple Mail 风格。
- 信息密度：紧凑高效。
- 邮件桌面结构：文件夹、邮件列表、邮件详情三栏同时可见。
- 主色：Apple 系统蓝。
- 实施方式：保留业务逻辑，系统性重构前端设计系统和页面结构。

## 3. 硬约束

1. 覆盖全部一级页面和全局浮层，不只处理某个设置项。
2. 不修改后端接口、认证、权限、邮件同步、缓存、附件、通知和数据库行为。
3. 不迁移或删除 `/Docker/flymail/data`，不改变容器内 `/data` 持久化结构。
4. 不新增或升级生产依赖。
5. 不改变一级导航名称和现有能力入口。
6. 页面必须继续支持浅色、深色、减少动态、减少透明和高对比偏好。
7. 主要交互控件保持不低于 44px 的可点击区域；高密度通过内部排版实现，不牺牲可用性。
8. 版本、README、镜像和部署文档按实际行为同步。

## 4. 视觉系统

### 4.1 色彩

- 主色使用系统蓝：浅色主题 `#0A84FF`，深色主题使用更亮的蓝色以保持对比度。
- 应用画布使用冷灰浅底，主要内容面使用白色或深色一级表面。
- 选中态使用低饱和蓝色填充，不使用大面积高饱和色块。
- 边框承担主要层级，阴影只用于菜单、弹窗、抽屉和悬浮内容。
- 成功、警告、危险继续使用语义颜色，不与主色混用。

### 4.2 排版

- 继续使用系统字体栈。
- 主页面标题收敛到 20–22px；工作台内部标题使用 15–17px。
- 正文使用 13–14px；辅助信息使用 11–12px。
- 邮件列表依靠字重、颜色和未读点区分状态，不重复堆叠多个文字标签。
- 数字、日期和状态保持稳定对齐。

### 4.3 几何与间距

- 页面圆角以 10–12px 为主，输入框和按钮为 8–10px。
- 页面桌面边距收敛到 16–20px，工作台边到边利用空间。
- 列表行视觉高度约 52–64px，但点击区域不低于 44px。
- 卡片只用于真正独立的信息组，不把每个字段都包成卡片。

### 4.4 动效

- 只对颜色、透明度、阴影和小范围位移做 120–220ms 过渡。
- 不对大段布局使用弹跳动画。
- `prefers-reduced-motion` 下停止非必要旋转、滑动和淡入。

## 5. 应用壳层

### 5.1 桌面侧边栏

- 展开宽度 232–248px，折叠宽度 64–72px。
- 品牌区、主导航区、底部通知和用户区使用统一几何。
- 导航项使用系统蓝选中态、细边框和浅色填充。
- 折叠态图标严格居中；顶部 Logo 与展开图标复用同一交互槽位。
- 辅助入口不与主要邮件入口争夺视觉权重。

### 5.2 移动抽屉

- 保持独立抽屉，不复用桌面折叠状态。
- 主导航、邮箱账号和文件夹使用清晰分组。
- 抽屉打开时锁定背景滚动，并保留 Escape 和遮罩关闭。

### 5.3 全局反馈

- Toast、确认框、通知抽屉、用户菜单统一圆角、阴影、焦点和状态色。
- 确认框不再依赖浏览器原生 `prompt` 风格的视觉语言；现有功能逻辑不改变。

## 6. 邮件工作台

### 6.1 桌面三栏

桌面宽度大于 1180px 时同时显示：

| 区域 | 初始宽度 | 责任 |
|---|---:|---|
| 文件夹栏 | 236px | 账号切换、文件夹、未读数量 |
| 邮件列表 | 390px | 搜索、筛选、邮件摘要、分页 |
| 邮件详情 | 剩余空间 | 详情工具栏、元信息、正文、附件 |

要求：

- 选中邮件后列表不消失。
- 文件夹、列表、详情分别拥有明确滚动区域。
- 列表和详情之间使用细分隔线，不使用多个浮动卡片。
- 没有选中邮件时，详情栏显示统一空状态。
- 邮件详情顶部操作区固定，正文单独滚动。
- 未读邮件使用蓝点、较高字重和轻微背景差异，移除冗余“未读/已读”标签。

### 6.2 中等宽度

在 961–1180px：

- 保留邮件列表和详情双栏。
- 文件夹栏由全局移动/紧凑导航入口打开。
- 详情存在时列表仍可见，避免频繁返回。

### 6.3 手机

在 960px 及以下：

- 使用文件夹 → 列表 → 详情的单主视图流程。
- 保留现有移动抽屉和滑动返回能力。
- 页面不得产生横向滚动。

## 7. 写信

- 写信区域使用单一编辑器面板，不堆叠多层卡片。
- 收件人、抄送、密送和主题采用紧凑表单行。
- 编辑工具栏按文本、插入、签名分组，并降低视觉噪声。
- 附件显示为紧凑文件行。
- 底部发送栏固定在编辑工作区底部，发送为系统蓝主按钮。
- 草稿、定时发送、上传和错误状态使用统一状态组件。

## 8. 其他页面

### 8.1 联系人

- 左侧搜索与联系人列表、右侧资料详情。
- 使用连续分栏，而不是多层卡片。
- 空状态和新增联系人表单复用公共组件。

### 8.2 聚合收件箱

- 顶部设置摘要、筛选和操作形成紧凑工具区。
- 邮件列表视觉与普通邮件列表一致。
- 账号选择不再使用过大的独立卡片。

### 8.3 账号管理

- 使用响应式两至三列账号卡或紧凑列表。
- 邮箱地址、服务商、在线状态和同步状态为主信息。
- 编辑、禁用和删除作为次级操作，危险操作不默认抢占主视觉。

### 8.4 同步管理

- 顶部显示关键汇总。
- 每个账号任务使用紧凑任务行或任务卡。
- 进度、阶段、失败原因和操作在稳定网格中对齐。

### 8.5 备份

- 账号选择、备份列表和详情沿用邮件工作台语言。
- 空状态、分页、附件和详情操作与邮件页一致。

### 8.6 设置、个人资料、第三方通知、关于

- 设置使用左侧分类导航和右侧设置内容；在窄屏变为顶部分段导航。
- 设置项按主题组织为连续 section，不为每一项创建独立大卡片。
- 个人资料使用头像和核心信息主区，字段与操作对齐。
- 第三方通知沿用设置页 section 结构。
- 关于页保持阅读宽度，但使用同一标题、列表和信息表面。

### 8.7 用户管理

- 桌面使用高密度表格化列表；移动端转为信息卡片。
- 账号状态、角色和操作具有明确优先级。

### 8.8 登录页

- 与登录后界面使用同一系统蓝、排版和表面层级。
- 保留明确错误提示、会话启动状态和可访问焦点。

## 9. 公共组件和样式职责

- `tokens.css`：语义颜色、字号、圆角、间距、阴影、控件尺寸和工作台栏宽。
- `base.css`：重置、字体、焦点、滚动条和系统偏好。
- `components.css`：按钮、输入框、选择框、开关、徽标、菜单、弹窗和状态组件。
- `app-shell.css`：侧边栏、移动抽屉、通知、用户菜单和全局浮层。
- `layout-system.css`：页面模板、宽度、页头、工具栏和滚动归属。
- `page-system.css`：邮件三栏、列表、详情、设置 section、管理列表和其他跨页面模式。
- 页面 scoped 样式：只保留页面独有布局，不继续定义通用按钮、输入框、页面背景或卡片外观。

现有 `UiButton`、`UiIconButton`、`UiCard`、`UiField`、`UiBadge`、`UiSegmentedControl`、`UiEmptyState`、`UiLoadingState`、`UiAlert`、`PageFrame`、`PageHeader`、`PageToolbar`、`UiPanel` 和 `UiScrollRegion` 继续复用，不新增 CSS 框架或图标库。

## 10. 响应式和无障碍

- 关键视口：1440×900、1920×1080、2560×1440、390×844。
- 工作台在宽屏充分利用空间，文档页保持舒适左对齐宽度。
- 所有图标按钮必须提供可访问名称。
- 键盘焦点使用清晰系统蓝焦点环。
- 异步保存和加载使用 `aria-live` 或等价可访问反馈。
- 深浅主题仅使用语义 token，不在页面样式中新增固定主题颜色。

## 11. 测试与验收

1. 前端静态回归测试覆盖系统蓝令牌、邮件三栏结构、设置导航、紧凑密度和移动断点。
2. `npm test` 全量通过。
3. `npm run build` 通过 Vue 类型检查和 Vite 生产构建。
4. 后端 `python -m unittest discover -s tests -v` 全量通过，证明 UI 改动未破坏接口契约。
5. `bash -n scripts/docker-entrypoint.sh`、Docker Compose 配置和 `git diff --check` 通过。
6. 构建本地 `benxianyu/flymail:<VERSION>` 镜像。
7. 使用独立临时目录和临时容器验证健康检查、MySQL 8.0、`/data` 目录、数据库读写、重启持久化、日志脱敏和安全关闭。
8. 安全替换当前 `flymail` 容器，保留 `/Docker/flymail/data:/data`，重启后健康和数据正常。
9. README 同步说明整站 Apple Mail 风格、真正桌面三栏和响应式行为。
10. 不上传 Docker Hub，除非用户另行明确要求。

## 12. 非目标

- 不改变邮件业务能力或数据模型。
- 不重写前端框架和状态管理。
- 不新增拖动栏宽等高风险复杂交互；本轮优先交付稳定三栏和一致视觉。
- 不迁移数据库、不删除用户数据、不改变认证方式。
