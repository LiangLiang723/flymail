# FlyMail 邮件列表视觉层级精修设计

## 1. 目标

在不改变邮件业务行为、搜索能力、同步逻辑、分页、会话和验证码复制功能的前提下，降低邮件列表与侧栏的重复视觉噪音，让界面更像邮件客户端而不是数据管理表格。

本轮只做减法式视觉精修，不重构应用骨架，不增加新的面板或依赖。

## 2. 已确认的交互约束

- 搜索继续留在当前桌面工具栏右侧这一行，不额外拆出第三行。
- `邮件 / 会话` 继续是一级列表显示模式切换。
- `全部 / 未读 / 已读 / 附件 / 星标` 继续是二级快速筛选。
- 移动端继续使用现有筛选折叠和统一侧栏抽屉。
- 验证码复制按钮保留。
- 不新增右侧常驻邮件预览栏。
- 不修改 `/Docker/flymail/data`、数据库、后端接口或环境变量。

## 3. 当前问题

### 3.1 已读状态重复强调

邮件行同时通过字重、颜色、状态图标和“已读/未读”徽标表达阅读状态。已读是大多数邮件的默认状态，持续显示“已读”徽标会形成重复噪音。

### 3.2 工具栏层级接近

当前文件夹上下文、`邮件 / 会话`、快速筛选都挤在相同视觉层级中。虽然功能正确，但扫描时不容易区分“当前位置”“显示模式”和“内容过滤”。

### 3.3 当前文件夹摘要重复未读数量

左侧上下文显示 `收件箱 · 未读 0`，快速筛选又显示 `未读 0`。同一数量在相邻区域重复。

### 3.4 账号与文件夹同时使用强选中态

当前邮箱账号和当前文件夹都使用强调色背景与左侧强调条。账号实际是持续上下文，文件夹才是当前邮件列表位置，应让文件夹承担更强的 active 表达。

### 3.5 邮件列表仍偏表格化

每行强分割线、重复状态徽标以及发件人/主题近似权重，使列表更像数据表。应通过留白、hover、未读字重和轻量分隔建立层级。

## 4. 方案比较

### 方案 A：只改 CSS，不改模板

保留所有状态节点，只通过 `display: none` 和颜色覆盖弱化。

优点：改动最小。缺点：DOM 仍保留无意义的已读徽标和账号 active 语义，后续维护容易再次把旧状态显露出来。

### 方案 B：语义模板小改 + 局部样式精修（采用）

- 邮件行只在未读时显示状态徽标；已读不渲染徽标。
- 当前账号只使用 `is-context`，不再使用强 `active`。
- 文件夹继续使用 `active`。
- 桌面工具栏保持单行，但通过分组 class 和样式让显示模式与快速筛选有清晰层级。
- 文件夹摘要只显示文件夹名，不重复未读数量。
- 弱化列表分隔线和已读文字，未读继续用左侧状态点与字重强调。

优点：语义与视觉一致，改动仍局限于现有组件。缺点：需要同步少量前端契约测试。

### 方案 C：重新拆成多行工具栏

将当前位置、显示模式、快速筛选和搜索拆成多行。

优点：层级最强。缺点：增加垂直占用，改变当前高密度桌面工作区，而且与本轮“搜索继续保持当前一行”的约束不符，因此不采用。

## 5. 具体设计

### 5.1 邮件工具栏

桌面保持现有单行骨架：

`[多选] [文件夹] [邮件 | 会话] [全部 / 未读 / 已读 / 附件 / 星标] ... [搜索] [全部已读] [刷新] [连接状态]`

但视觉层级调整为：

1. 文件夹名是当前位置，只显示 `收件箱`，不再附加 `未读 0` 或 `全部 N`。
2. `邮件 / 会话` 使用现有 segmented control，保持明确的一级模式边界。
3. 快速筛选保持轻量文本按钮，active 使用弱强调背景，不与 segmented control 同等厚重。
4. 搜索仍由 `MailSearchBar` 完整负责并保持固定高度；高级筛选仍是浮层，不参与工具栏高度计算。
5. 1180px 以下桌面继续按现有响应式规则收缩；不使用隐式 desktop wrap。

### 5.2 邮件行

- 已读邮件：不显示“已读”徽标，不显示已读信封图标；发件人与主题使用次级文字色。
- 未读邮件：保留左侧 4px 状态点，发件人使用 semibold，主题使用 medium；保留一个轻量 `未读` 徽标作为明确的非颜色状态提示。
- 会话模式：只有存在未读邮件时显示 `未读 N`；全部已读的会话不显示“已读”徽标。
- 附件回形针、验证码复制、日期继续保留。
- 日期保持最右固定列，不被主题挤掉。
- 行分割线改为更弱的语义边框混合色；hover 和 selected 继续承担行边界反馈。

### 5.3 侧栏账号与文件夹

- 写邮件继续使用最高优先级强调色按钮。
- 当前文件夹继续使用 `active`：弱强调背景 + 左侧强调条。
- 当前邮箱账号只使用 `is-context`：使用轻微填充背景和正常主文字，不显示左侧强调条。
- 非当前账号保持普通状态。
- 折叠态、重新授权状态、账号滚动和文件夹滚动保持现状。

## 6. 可访问性

- 未读状态不能只靠颜色，继续保留未读徽标与字重变化。
- 邮件行现有 `role="button"`、键盘 Enter/Space 和 `focus-visible` 保持。
- 纯图标刷新、移动筛选和重新授权按钮保持可访问名称。
- 搜索高级筛选的 `aria-expanded`、Escape 与外部点击关闭保持不变。

## 7. 测试与验收

自动化契约至少锁定：

1. 邮件行不再渲染普通已读徽标；未读邮件/未读会话仍有可见文字状态。
2. 桌面文件夹摘要只显示当前文件夹名，不重复未读/全部计数。
3. 当前账号只使用 `is-context`，文件夹仍使用 `active` 且只在邮件页激活。
4. 搜索仍位于工具栏右侧分组中，桌面 `toolbar-right` 不换行。
5. 未读状态点、未读字重和日期固定列仍存在。
6. 移动端隐藏行状态徽标的现有规则不回归，390×844 不产生横向溢出。

构建与浏览器验证：

- 前端完整测试和 `npm run build`。
- 后端完整 unittest 回归。
- `bash -n scripts/docker-entrypoint.sh`、`docker compose config`、`git diff --check`。
- Docker 构建真实镜像。
- 使用独立临时数据目录启动临时容器，验证健康、MySQL 8.0、`/data/mysql`、`/data/flymail`、数据库读写、重启持久化、日志脱敏、镜像无密码密钥元数据和安全停止。
- 浏览器至少检查 1440×900、1920×1080、390×844，以及 200% 缩放等价场景。

## 8. 文档与版本

本轮属于用户可见 UI 行为变化，需要在 README 的设计系统/邮件列表说明中同步“已读默认降噪、未读突出、账号为上下文、文件夹为强选中”的结果。

按 FlyMail 发布规则升级补丁版本，并通过 `npm run sync-version` 同步 `VERSION`、根 `package.json`、`frontend/package.json`、`docker-compose.yml` 和 README 镜像标签。
