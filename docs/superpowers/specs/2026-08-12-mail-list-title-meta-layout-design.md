# FlyMail 邮件列表标题附属图标布局设计

## 1. 背景

当前 `0.0.54` 邮件列表把验证码复制图标和附件图标统一放到日期左侧的动态元信息区：

```text
发件人 | 未读信封 + 主题                    | 复制 | 附件 | 日期
```

该结构解决了不同图标组合下日期对齐和间距不统一的问题，但视觉层级仍不理想：复制和附件更像邮件标题的附属信息，却被推到接近日期的位置，容易被理解成日期侧的操作/状态区。

用户确认新的方向是：

- 桌面端只让日期承担行尾锚点。
- 会话数量、验证码复制、附件图标都紧跟标题内容。
- 移动端保持 `0.0.54` 已验证过的两行布局，不把图标重新塞进标题行。

## 2. 目标

桌面端把邮件行调整为：

```text
发件人 | 未读信封 + 标题 + 会话数量 + 复制 + 附件          日期
```

并满足：

1. 日期始终是邮件行最右侧唯一固定锚点。
2. 会话数量属于标题主行；现有 `mail-meta-actions` 保持邮件行直接子项，但桌面视觉上紧跟标题主行，形成连续的标题附属信息簇。
3. 标题是这一连续内容簇中唯一允许主动收缩和省略的区域。
4. 会话数量、复制图标、附件图标和日期不得被长标题挤掉。
5. 同时存在时固定顺序为：`标题 → 会话数量 → 复制 → 附件`。
6. 没有某个附属项时不预留空槽位。
7. 移动端继续保持：日期右上、可选图标区右下。
8. 不改变验证码识别、附件检测/下载、会话聚合、日期格式、未读状态和邮件打开行为。

## 3. 桌面端布局

### 3.1 逻辑结构

桌面邮件行保持四个直接布局项：

```text
[发件人固定列] [mail-info：未读信封 + mail-title-content] [mail-meta-actions：复制 + 附件] [日期固定列]
```

桌面视觉顺序仍然形成一个连续内容簇：

```text
[未读信封] [标题，可收缩] [会话数量] [复制] [附件]          [日期]
```

`mail-title-content` 是本页内部的轻量包装层，只包含 `mail-subject` 和可选 `conversation-count`；`mail-meta-actions` 不移动进 `mail-info`。这样既能把标题→会话数量精确控制为 6px，又保留现有未读信封→标题的 8px，同时移动端仍可直接把 `mail-meta-actions` 作为 `mail-item` 的 grid item 放进右下 `meta` 区，不需要复制两套 DOM。

普通邮件四种状态：

```text
无图标：   ✉ 主题                                           14:00
只有附件： ✉ 主题  📎                                       14:00
只有复制： ✉ 主题  ⧉                                        14:00
两者都有： ✉ 主题  ⧉  📎                                    14:00
```

会话模式：

```text
✉ 主题  5  ⧉  📎                                            14:00
```

### 3.2 标题收缩规则

标题必须继续满足：

- `min-width: 0`
- 单行显示
- `overflow: hidden`
- `text-overflow: ellipsis`
- `white-space: nowrap`

桌面端不能继续让 `.mail-info { flex: 1 }` 吞掉整段剩余宽度，否则 `mail-meta-actions` 仍会被推到日期附近。桌面实现应把 `.mail-info` 调整为可按内容增长、空间不足时可收缩的 `flex: 0 1 auto`，并保持 `min-width: 0`；`.mail-main-row` 同样使用可收缩而不强制占满行尾的布局。

新增页面内 `.mail-title-content`：`display: inline-flex; align-items: center; gap: 6px; min-width: 0; flex: 0 1 auto`。现有 `.mail-main-row` 的 8px gap 继续只负责未读信封与 `mail-title-content` 之间的距离，因此不改变未读信封→标题的现有节奏。

标题继续承担可收缩空间，而会话数量、复制和附件全部 `flex-shrink: 0`。当空间不足时，只截断标题：

```text
✉ 这是一个非常非常长的邮件标题需要被截断…  5  ⧉  📎    14:00
```

而不是隐藏或挤压附属项。

## 4. 会话数量

现有 `conversation-count` 继续只在会话模式且 `message_count > 1` 时显示。

桌面端顺序固定为：

```text
标题 → 会话数量 → 复制 → 附件
```

约束：

- 会话数量不改变现有语义和数据来源。
- 不新增固定占位。
- 会话数量 `flex-shrink: 0`。
- 与标题或下一附属项保持同一套内容簇间距。

## 5. 验证码复制图标

复制按钮继续保持 `0.0.54` 的交互能力：

- 纯图标。
- `title="复制验证码"`。
- 保留动态 `aria-label`。
- 点击只复制验证码，不打开邮件行。
- 保留 `focus-visible`。
- 交互尺寸继续为 `28px × 28px`。
- 内部 SVG 继续为 `15px × 15px`。
- 不恢复额外左右 margin。

桌面端不复制或迁移按钮 DOM；现有 `mail-meta-actions` 仍位于 `mail-info` 之后，但通过新的 flex 分配视觉上直接跟随会话数量，并保持复制在附件之前。

## 6. 附件图标

附件图标继续是状态指示，不是按钮：

- 不新增 hover 背景。
- 不改变邮件行点击行为。
- 不新增附件下载入口。
- 尺寸继续为 `15px × 15px`。
- 使用现有 tertiary 层级颜色。
- `flex-shrink: 0`。

桌面端位于标题内容簇最后，因此只要附件存在，它就是标题附属项中最右侧的图标。

## 7. 间距

桌面标题内容簇采用统一的紧凑节奏：

- 未读信封与标题继续使用当前 `.mail-main-row` 的 `8px` 间距。
- 标题与会话数量之间：`6px`。
- `mail-info` 与 `mail-meta-actions` 之间：`6px`，因此没有会话数量时标题→第一个图标也是 6px。
- `mail-meta-actions` 内复制与附件之间：`6px`。
- 日期与前方标题内容簇之间固定 `12px` 的独立安全距离。

日期的间距不再由图标容器控制。桌面日期使用独立的 `12px` 左侧安全 inset，并通过 `margin-left: auto` 吸收标题内容簇之后的剩余空间；即使没有会话数量、复制和附件，日期仍然保持相同的行尾位置。为继续保留当前 58px 日期文本轨道，桌面日期总预留宽度固定为 `70px`（12px 左侧安全 inset + 58px 日期文本区），移动端继续覆盖为 `width: auto; padding: 0; margin: 0`。

## 8. 日期

日期继续作为唯一的右侧固定列：

- 始终位于邮件行最右。
- `flex-shrink: 0`。
- 桌面总预留宽度固定 `70px`，其中左侧 `12px` 为安全 inset，右侧 `58px` 为现有日期文本轨道。
- 文本右对齐。
- 使用 `margin-left: auto` 把剩余空间留在标题附属簇与日期之间。
- 不因为标题长度或图标组合发生横向跳动。
- 与前方内容簇之间的 12px 安全距离由日期自身承担，不再与 `mail-meta-actions` 绑定。

## 9. 移动端保持不变

移动端明确不采用桌面标题伴随图标布局。

继续沿用 `0.0.54` 已验证结构：

```text
发件人                               日期
    未读信封 + 主题              复制  附件
```

也就是：

- 日期继续使用右上 `date` grid area。
- `mail-meta-actions` 继续使用右下 `meta` grid area。
- `mail-title-content` 在移动端覆盖为 `flex: 1 1 auto; min-width: 0`，只负责让标题/会话数量在 `info` 区正常收缩，不改变 meta 区位置。
- 同时存在时仍为 `复制 → 附件`。
- 只有一个图标时，该图标独占右下 meta 区。
- 没有图标时不预留空槽位。
- 不把移动端复制或附件重新放回主题文本流。
- 390×844 不得出现页面级横向滚动。

因此本轮必须使用响应式差异：桌面端图标跟随标题，移动端继续右下固定区域。

## 10. 实现边界

本轮只调整邮件列表现有 DOM/CSS 布局，不新增公共组件或第三方依赖。

## 11. TDD 验收契约

实现前先新增失败测试，锁定以下行为：

1. 桌面 DOM 继续保持 `mail-info → mail-meta-actions → mail-date`，不复制第二套验证码/附件图标 DOM。
2. `mail-info` 内新增 `mail-title-content`，其内部顺序固定 `mail-subject → conversation-count`；随后 `mail-meta-actions` 内部顺序固定 `verification-code-copy → att-badge`，因此整体视觉/DOM 顺序为 `mail-subject → conversation-count → verification-code-copy → att-badge → mail-date`。
3. `mail-date` 位于完整标题附属内容之后，并保持独立固定行尾列。
4. 桌面 `.mail-info` 使用 `flex: 0 1 auto` 且 `min-width: 0`，不能继续以 `flex: 1` 把图标推向日期；`.mail-title-content` 使用 `flex: 0 1 auto; min-width: 0; gap: 6px`；标题可收缩，会话数量、复制、附件都 `flex-shrink: 0`。
5. `.mail-main-row` 保留未读信封→标题的 8px；`mail-title-content` 内标题→会话数 6px；`mail-info`→`mail-meta-actions` 6px；`mail-meta-actions` 内复制→附件 6px。
6. 日期桌面总宽度为 `70px`，内部左侧安全 inset 精确 `12px`，日期文本轨道保持 `58px`，并使用 `margin-left: auto`。
7. 没有会话数/复制/附件时不渲染对应空槽。
8. 移动端 `mail-title-content` 必须恢复为可占满 `info` 区的 `flex: 1 1 auto; min-width: 0`，同时继续使用 `"select sender date" / "select info meta"` 两行 grid。
9. 移动端 `mail-meta-actions` 继续 `grid-area: meta`、右对齐，并保持 `复制 → 附件`。
10. 390px 移动端继续禁止页面级横向溢出。

测试不能只检查字符串存在；必须同时检查桌面 DOM 顺序和移动端 grid 契约，避免实现为了桌面调整而破坏移动端。

## 12. 浏览器验收

使用真实 production build 和安全模拟 API 数据，至少构造：

1. 普通邮件，无附件/验证码。
2. 只有附件。
3. 只有验证码。
4. 同时有附件和验证码。
5. 会话模式，带 `message_count`、验证码和附件。
6. 一条超长中文主题或无空格长主题。

### 1440×900 / 1920×1080

确认：

- 图标真实紧跟标题，而不是靠近日期。
- 会话模式顺序是 `标题 → 数量 → 复制 → 附件`。
- 只有一个图标时直接跟标题，不预留另一图标空槽。
- 长主题只截断主题，不压掉数量、复制、附件和日期。
- 日期所有行严格右对齐。
- 标题附属项与日期之间有清晰空白，不粘连。

### 390×844

确认：

- 日期仍在右上。
- 图标仍在右下。
- 两图标同时存在时复制在左、附件在右。
- 桌面端的标题伴随布局没有泄漏到移动端。
- 无页面级横向滚动。

### 720×450（200% 等价）

确认：

- 标题可正确收缩。
- 附属图标和日期保持可访问、可见。
- 不产生页面级横向溢出。

## 13. 文档与版本

README 中当前描述“验证码复制和附件状态统一放入日期左侧动态元信息区”，实现后必须同步修改为：

- 桌面端会话数量、复制和附件紧跟标题。
- 日期独立固定最右。
- 移动端仍保持日期右上、图标右下。

本轮是用户可见布局调整，预计发布版本从 `0.0.54` 升级到 `0.0.55`。

`VERSION` 仍为版本唯一事实来源，并同步：

- 根 `package.json`
- `frontend/package.json`
- `docker-compose.yml`
- README 镜像标签

不新增环境变量，因此 `.env.example` 无需变化。

## 14. 验收标准

1. 桌面复制和附件不再靠近日期，而是紧跟标题。
2. 桌面会话模式顺序严格为 `标题 → 会话数量 → 复制 → 附件`。
3. 附件存在时仍是标题附属图标中最右侧的图标。
4. 标题是唯一可主动收缩/ellipsis 的内容。
5. 图标和会话数量不会被长标题挤掉。
6. 日期继续作为唯一最右固定列，并且各行严格对齐。
7. 桌面保留未读信封→标题 8px；标题→会话数、标题主行→图标区、复制→附件均为 6px；日期使用精确 12px 左侧安全 inset，并保留 58px 日期文本轨道。
8. 缺失附属项不产生空槽。
9. 移动端保持 `0.0.54` 的日期右上、图标右下布局不变。
10. 390×844、1440×900、1920×1080、720×450（200% 等价）无页面级横向溢出。
11. 不改变验证码识别、附件逻辑、会话逻辑、未读状态、搜索、发件人列或正式数据。
