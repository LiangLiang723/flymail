# 验证码复制后自动标记已读设计

## 目标

用户在邮件列表点击验证码复制图标，并且验证码成功写入剪贴板后，把这一封邮件标记为已读；复制按钮仍然不能打开邮件详情或进入多选。

## 方案

复用现有 `/api/mark-read` 与前端乐观更新逻辑，不新增后端接口、数据库字段或同步机制。

- 复制按钮把当前 `Message` 传给 `copyVerificationCode()`，而不是只传验证码字符串。
- 剪贴板写入成功后，若该邮件仍未读且当前文件夹支持已读状态，则立即在前端把该邮件显示为已读，并异步调用 `/api/mark-read`。
- `/api/mark-read` 继续负责更新本地缓存、文件夹未读计数、WebSocket 状态通知，并在远端 IMAP 暂时失败时进入 `pending_read_sync` 重试队列。
- 邮件原本已经已读时，不重复调用标记已读接口。
- 剪贴板写入失败时只显示复制失败，不改变邮件已读状态。

## 前端状态更新

把 `selectMessage()` 里现有的单封邮件乐观已读更新抽成可复用函数，统一处理：

1. `messages` 当前行的 `is_read`；
2. 会话模式的 `unread_count` 与 `conversationMessages`；
3. 当前筛选计数；
4. 侧栏当前文件夹未读数与列表计数刷新；
5. 异步 `/api/mark-read` 请求。

打开未读邮件和复制未读邮件验证码都调用同一函数，避免两套已读状态逻辑发生偏差。

## 错误处理

- 剪贴板主路径失败后继续使用当前 legacy copy 兜底。
- 只有最终复制成功才触发已读更新。
- 标记已读接口保持当前非阻塞行为；远端同步失败由后端既有 pending 队列处理，不回滚已经完成的复制操作或本地乐观状态。

## 数据与安全边界

- 不修改数据库 schema。
- 不修改 `/data` 目录结构或正式持久化数据迁移。
- 不记录验证码内容。
- 不新增生产依赖。

## 验收

1. 未读验证码邮件复制成功后，当前列表立即显示为已读。
2. 同一次操作异步调用 `/api/mark-read`，参数包含当前邮件 ID、文件夹和账号 ID。
3. 文件夹未读计数随之减少一次；不会重复减少。
4. 已读邮件复制验证码时不重复发送标记已读请求。
5. 复制失败时邮件仍保持未读。
6. 复制按钮继续阻止邮件行点击，不打开详情。
7. 打开邮件原有自动标记已读行为保持不变。
8. 后端现有标记已读、pending read sync 与用户数据隔离逻辑保持不变。
