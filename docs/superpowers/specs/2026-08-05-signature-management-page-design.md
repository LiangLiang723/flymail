# 独立签名管理页面设计

## 背景与根因

当前写信页把签名选择、内置模板、签名列表和富文本编辑器全部嵌套在一个宽约 `320px`、带滚动裁剪的下拉面板中。富文本工具栏的字体、字号、颜色、行距和表格菜单又依赖 `hover/focus-within` 显示，点击菜单后焦点没有可靠释放，多个菜单会同时展开并互相遮挡。继续调整面板宽度或 `z-index` 只能缓解局部表现，不能解决狭窄容器、嵌套滚动、移动端编辑和离开写信页时的状态保存问题。

本次采用“设置体系下的独立签名管理页面”：不把签名加入主侧边栏一级导航；写信页只保留快速选择，完整编辑跳转到独立页面。

## 目标

1. 签名新建、编辑、复制、删除和默认规则管理都在完整页面中完成。
2. 写信页的签名入口只承担快速切换，不再承载编辑器或复杂模板管理。
3. 从写信页进入签名管理后，返回时完整保留收件人、主题、正文、附件、发件邮箱和草稿标识。
4. 富文本工具栏任意时刻只允许一个下拉菜单打开，点击外部或按 `Escape` 可以关闭。
5. 继续复用现有用户隔离、账号范围和新邮件/回复默认规则，不迁移或删除现有签名数据。

## 信息架构与入口

签名管理页的视图键为 `signatures`，归入设置体系，但不出现在主侧边栏的一级导航中。

提供三个入口：

- **写信页签名菜单：** 底部提供“管理签名”，进入页面时记录来源为写信页。
- **设置页：** 新增“邮件签名”入口卡片，展示签名数量和默认规则说明。
- **用户菜单：** 在“第三方通知”和“设置”附近增加“签名管理”快捷入口。

页面顶部返回按钮遵循来源：

- 从写信页进入：返回写信页并恢复原编辑状态。
- 从设置页进入：返回设置页。
- 从用户菜单直接进入：返回设置页。

侧边栏的邮件、联系人、同步、账号和备份入口保持不变。

## 写信页快速签名菜单

写信页删除以下内容：

- 内置模板网格。
- 内嵌签名编辑弹窗。
- 内嵌签名删除操作。
- 在下拉面板中管理默认规则。

签名菜单只保留：

1. 当前发件邮箱可用的签名列表。
2. 当前签名选中状态。
3. “无签名”。
4. “管理签名”。

列表项显示签名名称、适用邮箱和默认标识。点击列表项立即替换 FlyMail 管理的签名块，不重复追加；点击“管理签名”先保存写信会话快照，再跳转独立页面。

## 写信状态保存

不自动向远端邮箱创建草稿，也不依赖组件缓存。`mailStore` 增加仅存在于当前浏览器会话的写信工作区快照，包含：

- 发件邮箱。
- 收件人、抄送和密送。
- 主题和 HTML 正文。
- 已上传附件的前端记录与服务器路径。
- `draft_message_id`、`draft_folder` 和写信场景。
- 抄送/密送展开状态。

从签名管理返回写信页时优先恢复该快照，并且不得重新插入默认签名。快照恢复后保留，发送、明确放弃邮件或加载另一封草稿时再清除。页面刷新不承诺保留尚未保存的写信内容；现有“保存草稿”仍是跨刷新持久化方式。

## 页面布局

使用现有 `PageFrame` 管理工作台和分栏页面模式，最大化利用桌面宽度。

### 桌面端

- 顶部：返回按钮、标题“签名管理”、说明文字、“新建签名”主按钮。
- 左栏约 `320px`：搜索、适用邮箱筛选、签名列表和空状态。
- 右栏：签名表单与富文本编辑器。
- 底部操作条：删除、取消更改、保存。

左栏列表项显示：

- 签名名称。
- “全部邮箱”或具体邮箱地址。
- “新邮件默认”和“回复/转发默认”徽标。
- 当前选中状态。

列表按创建顺序稳定显示；本次不增加拖拽排序，因为写信菜单的主要识别依据是名称和默认规则，而不是手工顺序。

### 移动端

- 默认显示签名列表。
- 点击签名或“新建签名”后进入占满页面的编辑视图。
- 编辑视图顶部提供返回列表、保存和更多操作。
- 不使用居中弹窗或底部抽屉承载富文本编辑器。

## 新建与模板

点击“新建签名”进入空白编辑状态，并提供以下起点：

- 空白签名。
- 简洁商务。
- 联系方式。
- 品牌卡片。
- 极简落款。

模板只负责填充新建表单，不作为写信页中可直接插入的临时签名。选择模板后仍需填写名称并保存，确保所有可用签名都由后端持久化和管理。

## 编辑表单

字段包括：

- **签名名称：** 必填，去除首尾空格，最长沿用后端 `255` 字符限制。
- **适用邮箱：** “全部邮箱”或当前用户拥有的一个邮箱。
- **新邮件默认：** 同一用户、同一邮箱范围内唯一。
- **回复/转发默认：** 同一用户、同一邮箱范围内唯一。
- **签名正文：** 富文本 HTML，沿用后端 `10000` 字符限制。

保存默认签名时，后端继续清除同一用户、同一邮箱范围内旧的同类默认项。前端保存后重新加载完整签名列表，并提示“已替换该范围原有默认签名”，避免用户误以为存在多个默认项。

签名名称不强制全局唯一；相同名称可以存在于不同邮箱范围。列表同时显示邮箱范围，避免混淆。

## 富文本编辑器交互

`TiptapEditor` 的下拉菜单从 CSS `hover/focus-within` 改为显式点击状态：

- 使用单一 `activeDropdown` 标识当前打开菜单。
- 点击另一个工具栏下拉时关闭前一个。
- 再次点击同一个按钮关闭。
- 点击编辑器外部、滚动页面或按 `Escape` 关闭。
- 选择菜单项后立即关闭菜单并恢复编辑器焦点。
- 下拉按钮提供 `aria-expanded` 和 `aria-controls`。

工具栏允许换行，但下拉层不参与工具栏布局，不会把其他按钮挤开。签名编辑页使用完整可用宽度；移动端工具栏按功能组换行，菜单宽度受视口约束。

表格功能保留，但只有当前激活的表格菜单可见。颜色、字体、字号、行距、表格和表情菜单不能同时打开。

## CRUD 与未保存状态

- **新建：** `POST /api/signatures`。
- **保存修改：** `PUT /api/signatures/{id}`。
- **复制：** 以“原名称 - 副本”为初始名称，通过 `POST` 创建，默认标识全部关闭，避免复制操作改变现有默认规则。
- **删除：** 明确确认后调用 `DELETE /api/signatures/{id}`。

表单内容与最后一次加载/保存快照不一致时标记为未保存：

- 切换列表项或新建另一签名前弹出确认。
- 点击页面返回按钮时弹出确认。
- 浏览器刷新或关闭标签页时使用 `beforeunload` 提示。
- `App.vue` 的视图切换入口在离开签名管理页前读取签名工作区的未保存状态；用户确认放弃后才切换，取消则留在当前页面。
- 编辑草稿同时保存在 Pinia 签名工作区状态中，组件重绘或移动端列表/编辑视图切换不会丢失内容。

删除当前正在写信中使用的签名不会修改已经插入正文的 HTML；后续重新选择时该签名不再出现。

## 加载、错误与空状态

- 首次加载显示共享加载状态。
- 无签名时左栏显示说明和“创建第一个签名”。
- 保存期间禁用重复提交，并在按钮中显示加载状态。
- API 失败时保留表单内容，显示可操作错误，不关闭编辑状态。
- 删除失败时保留签名及选中状态。
- 当前用户没有邮箱账号时仍允许创建“全部邮箱”签名，邮箱选择器只显示该选项。
- 正文为空允许保存纯文本名称对应的空签名，但写信菜单插入时不会生成空签名块；界面提示“该签名没有正文”。

## 组件边界

新增：

- `frontend/src/views/SignatureManagement.vue`：页面编排、加载状态、来源返回和未保存管理。
- `frontend/src/stores/signatures.ts`：签名 CRUD、筛选、默认标识、进入来源、编辑草稿和未保存状态。
- `frontend/src/views/SignatureManagement.vue` 内部保持列表区和编辑区两个明确区域；本次不新增通用表单框架。

修改：

- `App.vue`：注册 `signatures` 视图，统一签名页进入/离开导航，并在未保存时确认。
- `UserMenu.vue`：增加快捷入口。
- `Settings.vue`：增加入口卡片。
- `ComposeEmail.vue`：精简签名菜单、保存/恢复写信快照。
- `stores/mail.ts`：增加写信工作区快照和签名页面返回来源。
- `TiptapEditor.vue`：改为单一点击式下拉状态。

后端现有签名接口和数据模型能够满足本设计，默认不新增数据库字段或环境变量。只有实施中发现现有接口无法返回必要状态时，才做最小接口补充。

## 测试与验收

### 前端自动化测试

- `App.vue` 注册独立签名视图，且主侧边栏不增加签名一级入口。
- 设置页和用户菜单包含签名管理入口。
- 写信页签名菜单不再包含富文本编辑器和模板网格。
- 从写信页进入、返回后完整恢复写信快照，并且不重复应用默认签名。
- 签名列表搜索、邮箱筛选和默认徽标正确。
- 新建、编辑、复制、删除调用正确 API。
- 复制签名时两个默认标识强制关闭。
- 未保存切换和返回需要确认。
- Tiptap 任意时刻只有一个下拉菜单处于打开状态，点击外部和 `Escape` 可关闭。

### 浏览器验证

使用真实页面验证截图中的失败路径：

1. 打开签名编辑器。
2. 依次点击字体、字号、颜色、行距和表格。
3. 每一步只显示当前菜单，无重叠、裁剪或水平溢出。
4. 在桌面和移动视口完成新建、保存、重新进入和删除。
5. 从带收件人、正文和附件的写信页进入签名管理，返回后内容完整保留。

## 文档、版本与数据影响

README 更新签名入口、独立管理页和写信状态保存边界。本功能不新增环境变量，不修改 `/Docker/flymail/data` 的目录结构，不删除或迁移现有签名。

实施版本从 `0.0.34` 升级到 `0.0.35`，通过 `npm run sync-version` 同步 `VERSION`、两个 `package.json`、`docker-compose.yml` 和 README 镜像标签。默认只构建本地镜像，不上传 Docker Hub。
