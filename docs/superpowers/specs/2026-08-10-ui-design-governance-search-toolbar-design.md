# FlyMail UI 设计治理与搜索工具栏稳定性设计

## 1. 目标

把 FlyMail 已经形成但分散在历史设计文档、README 和局部测试中的 UI 规则，收敛为根目录 `DESIGN.md` 的长期设计契约，并修复邮件搜索筛选条件把列表工具栏撑高的问题。

本次工作的核心不变量是：**状态可以改变内容，但不能无意改变工作区骨架。** 搜索条件、邮箱地址、主题、错误文案、标签数量等动态内容必须服从既定容器尺寸；需要展示完整信息时，应通过可换行内容区、滚动区或浮层承载，而不是让固定工具栏随内容增长。

## 2. 当前根因

### 2.1 搜索筛选摘要参与正常布局

`frontend/src/components/mail/MailSearchBar.vue` 当前把已应用筛选渲染为 `.mail-search-summary`，该元素位于 `.mail-search-main` 下方的正常文档流中，并允许 chips 换行。启用筛选后，搜索组件自然增加一行或多行高度，父级 `.list-toolbar` 随之增高。

### 2.2 桌面工具栏右侧允许隐式换行

`frontend/src/views/MailList.vue` 的桌面规则为 `.toolbar-right { flex-wrap: wrap; }`。搜索按钮、清除按钮、刷新按钮和状态元素随宽度变化时可以隐式换到下一行，也会改变工具栏高度。移动端本来就有显式的两段式布局，因此桌面端不需要依靠隐式换行兜底。

### 2.3 既有约束没有成为全局入口

此前 `3b71415` 已经修复过收件人标签、联系人候选、账号分组、Toast 和确认文案被动态内容撑高或撑破的问题，并增加了局部布局测试；现有 README 也写了动态内容应受容器约束。但是这些规则没有一个根目录级、AI 必须读取的事实来源，新的搜索组件因此重复出现了同类问题。

## 3. 参考原则

本设计吸收以下成熟规范的通用原则，但不引入它们的运行时依赖：

- W3C CSS Flexbox 规范：flex item 的自动最小尺寸可能由内容决定，需要在可收缩的 flex/grid 子项上显式使用 `min-width: 0` / `min-height: 0`，避免内容反向决定布局。
- GitHub Primer：设计模式应当可复用、稳定，并优先建立在已有 primitives 与 tokens 上；紧凑单行内容可使用明确的截断策略，但能正常换行或需要完整阅读的内容不应为了布局而盲目截断。
- Carbon Design System：overflow 是显式设计决策，应选择截断、渐进披露、滚动等策略，而不是让内容无边界增长。
- Radix Popover：菜单、高级筛选等浮层应脱离主布局流，并限制在可用视口内；FlyMail 继续使用现有 Vue/CSS 能力实现，不新增 Radix 依赖。
- Ant Design Select：大量选择状态不应无限扩张控制器，可以用数量摘要和进一步展开代替无上限标签展示。

参考地址：

- https://www.w3.org/TR/css-flexbox-1/
- https://primer.style/product/contribute/design/
- https://primer.style/accessibility/patterns/truncation/
- https://carbondesignsystem.com/patterns/overflow-content/
- https://www.radix-ui.com/primitives/docs/components/popover
- https://ant.design/components/select-cn

## 4. 根目录 `DESIGN.md` 的职责

`DESIGN.md` 是 FlyMail 用户界面设计、布局和交互约束的事实来源。它不记录一次任务的实现细节，而记录跨页面长期成立的设计不变量。

`AGENTS.md` 只增加入口规则：任何前端 UI、布局、组件或视觉修改前必须先读取 `DESIGN.md`。详细设计约束只维护在 `DESIGN.md`，不在两份文件重复。

历史 `docs/superpowers/specs/` 继续记录单次功能为什么这样设计；README 继续描述用户可见能力；`DESIGN.md` 决定以后 UI 应该遵守什么。

## 5. `DESIGN.md` 的核心契约

### 5.1 稳定骨架

- 应用壳、页面框架、页头、固定工具栏、导航行和固定控制行不得由动态内容决定高度或宽度。
- 桌面工具栏默认是一行稳定控制带；只有明确响应式断点才能改变为多行或纵向结构。
- 加载、空状态、筛选数量、错误、同步状态等状态变化不能造成页面骨架跳动，除非产品行为明确要求展开一个内容区域。

### 5.2 动态内容服从容器

- flex/grid 中承载可变内容的子项默认考虑 `min-width: 0`；需要填满剩余空间的 grid 列优先 `minmax(0, 1fr)`。
- 固定操作、图标、状态点、按钮使用 `flex-shrink: 0` 或等价固定轨道，不能被长文本挤没。
- 紧凑单行身份信息（邮箱、名称、主题、标签）允许 ellipsis，并在有必要时提供 `title`、详情区或其他完整信息入口。
- 正文、错误说明和需要完整阅读的内容优先换行，长无空格字符串使用 `overflow-wrap: anywhere`。
- 表格、邮件正文等确实需要宽内容时，只能由明确的滚动 owner 承担横向滚动，不能把页面根节点撑宽。

### 5.3 大量状态采用渐进披露

- 工具栏不能用无限 chips 表示所有状态。
- 多个筛选条件在工具栏只显示固定大小的摘要，例如 `筛选 4`；完整条件在筛选浮层中可见。
- 需要显示大量标签时采用数量、折叠、弹层或专用内容区，而不是继续增加固定控制的行数。

### 5.4 浮层不参与主布局

高级筛选、菜单、下拉选项、日期选择器等临时界面应使用 absolute/fixed/现有 overlay 模式，脱离主布局尺寸计算，并限制最大宽高。浮层需要保持键盘焦点、可访问名称、Escape/关闭路径和窄屏可用性。

### 5.5 滚动责任唯一

继续遵守现有 PageFrame/UiScrollRegion 契约：普通页面由页面主体滚动；工作台由明确的列表/详情面板滚动；一个视觉区域只能有一个主滚动 owner。页面根、面板和列表不得无意同时争夺相同方向的滚动。

### 5.6 Token 和样式职责

- `frontend/src/styles/tokens.css` 是颜色、间距、控件尺寸、圆角、阴影、页面尺寸和运动参数的事实来源。
- 页面业务样式使用语义 token，不新增固定调色板。
- `layout-system.css` 负责 PageFrame/PageToolbar/滚动等结构；`components.css` 负责共享控件；页面 scoped CSS 只负责页面独有结构。
- `macos.css` 是兼容层，不新增新的设计规则。

### 5.7 响应式和无障碍

- 沿用已有断点，不为了单个控件再创建相近的新断点：应用壳以 960px 切移动导航，邮件工作台现有窄屏规则继续按页面既有断点处理。
- 390×844 不允许页面级横向溢出；桌面 1440/1920 宽度下固定工具栏不因状态数量改变高度。
- 关键 UI 需要检查浏览器放大/字号增加到 200% 后是否仍能读取和操作。
- 可交互控件必须有清晰 `:focus-visible`、可访问名称；移动主要触控目标遵守现有 44px token。

## 6. 本次搜索工具栏设计

### 6.1 桌面

工具栏保持一行稳定控制带。搜索区内部结构固定为：

`搜索输入框 | 筛选 N | 搜索 | 清除（有条件时）`

其中 `N` 是当前高级筛选条件数。删除工具栏下方 `.mail-search-summary` chips；筛选条件的完整内容仍保留在高级筛选浮层的字段值中，因此不会损失编辑能力。

搜索组件必须允许自身收缩：根和输入包裹层 `min-width: 0`，固定按钮不换行且不参与动态高度增长。桌面 `.toolbar-right` 明确 `flex-wrap: nowrap`。

### 6.2 窄屏

保留当前明确的响应式结构：在既有断点下，整条工具栏可以主动切成两段；搜索区内部仍不因筛选数量增加新行。高级筛选在手机上继续使用 fixed 面板并限制视口高度。

### 6.3 可访问状态

筛选按钮除可见数量外，其 `aria-label` 应表达当前是否有已应用条件，例如 `筛选邮件，已应用 4 个条件`。筛选浮层仍通过 `aria-expanded` 暴露打开状态。

## 7. 自动化设计契约

新增两类测试：

1. `design-contract.test.mjs`：确保根目录 `DESIGN.md` 存在、`AGENTS.md` 强制 UI 修改前读取它，并锁定关键长期规则（稳定工具栏、动态内容、滚动、token、极端内容验证）。
2. `mail-search-layout.test.mjs`：确保搜索组件不再渲染正常流筛选摘要，仍显示筛选数量；搜索根和输入可收缩；桌面工具栏右侧禁止隐式换行，而移动端保留显式响应式布局。

静态契约之外，生产构建还要做真实浏览器检查：桌面开启多个筛选条件前后比较工具栏高度；手机宽度检查页面横向溢出；必要时检查 200% 缩放。

1. 桌面端应用 0、1、5、10 个筛选条件时，邮件列表工具栏高度保持一致。

4. 390×844 视口无页面级横向溢出，移动筛选面板可滚动且不撑开页面。
5. 根目录 `DESIGN.md` 成为 UI 设计契约，`AGENTS.md` 明确要求 UI 修改前读取它。
6. 设计契约测试、前端全量测试/类型检查/生产构建、后端全量测试、Shell、Docker Compose、镜像构建与真实临时容器验证全部通过。
