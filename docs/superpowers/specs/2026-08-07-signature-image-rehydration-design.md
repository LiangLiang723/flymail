# 签名图片兼容与重新水合设计

## 目标

修复两类关联回归：旧签名中的邮件附件图片在可缩放编辑器中出现破图，以及签名保存后重新选择时需要刷新页面才能重新显示图片。

## 已确认根因

1. 生产数据库中的现有签名仍引用旧的 `/api/messages/{uid}/attachments/{part}` 邮件附件地址，而不是稳定的 `/api/signature-images/{image_id}`。对应附件缓存对象仍存在并可用当前用户会话正常读取，因此文件没有丢失。
2. 新上传的签名图片文件已经写入 `/data/flymail/files/signature-images/`，但现有签名 HTML 尚未引用这些稳定文件。
3. `0.0.37` 新增的可缩放图片 NodeView 在初始同步时把已保存宽度再次按编辑器当前 `clientWidth` 夹取；编辑器刚重建或尚未完成布局时该宽度可能为 0/1px，造成图片视觉上消失，只有整页刷新后重新创建 NodeView 才恢复。
4. 签名管理页重新选择当前签名时不会强制重新水合编辑器，无法主动恢复已经进入错误显示状态的图片节点。

## 设计

### 旧图片兼容升级

读取当前用户签名列表时扫描签名 HTML 中的 `<img src>`。只处理 FlyMail 自己的邮件附件 URL：解析 `account_id`、`folder`、消息 UID 和附件 part，校验邮箱属于当前用户，并且只使用已经存在的本地缓存对象。找到本地图片后复制到签名图片目录，生成新的公开签名图片地址并更新签名 HTML。

迁移只复制文件并替换签名中的 URL，不删除旧邮件、旧附件、缓存对象或任何用户数据。无法验证、无法读取或不是当前用户资源的 URL 保持原样。

### 编辑器重新水合

可缩放图片初始渲染直接采用 HTML 中持久化的像素宽度，不再用尚未稳定的容器宽度重新夹取。`max-width: 100%` 继续负责窄容器适配；用户主动拖拽或点击百分比按钮时仍使用实际可见编辑器宽度做边界限制。

签名保存成功、重新选择签名和点击当前签名时递增编辑器 revision，通过 Vue `key` 重新创建 TiptapEditor，使编辑器始终从 Pinia 中已保存的签名 HTML 建立全新的 ProseMirror 文档和图片 NodeView，不依赖整页刷新。

## 验收

- 现有旧邮件附件签名图片自动转换为 `/api/signature-images/`，旧附件仍存在。
- 已保存 `width="367"` 的图片即使在初次布局宽度为 0 时也不会被渲染成 1px。
- 保存后点击其他签名再点回来立即显示，无需刷新。
- 点击当前签名也会重新加载其已保存内容。
- 新上传图片、25/50/75/100 快捷尺寸和拖拽尺寸保持正常。
- 后端、前端全量测试、生产构建、Docker 临时容器和当前生产容器验证全部通过。
