# FlyMail 邮件优先侧边栏重构设计

## 1. 目标

把 FlyMail 当前“全局功能侧栏 + 邮件页内部账号/文件夹侧栏”的双侧栏结构，重构为“邮件导航侧栏 + 功能菜单”的单侧栏信息架构。

核心原则：

- 左侧永久侧栏只承载高频邮件工作流：写邮件、聚合收件箱、邮箱账号、文件夹、通知、用户入口。
- 联系人、同步管理、账号管理、邮件备份等低频功能进入用户头像菜单。
- 桌面端始终保留邮件导航侧栏；进入联系人、同步管理、设置等页面时不改变应用骨架。
- 移动端与桌面端复用同一份侧栏内容结构，仅通过 960px 断点切换为抽屉。
- 不修改后端 API、认证、数据库、同步逻辑和 `/data` 持久化。

## 2. 当前问题

### 2.1 桌面端存在两层导航

当前应用壳 `AppSidebar.vue` 承载一级功能导航；`MailList.vue` 内又有独立的 `220px` 邮箱账号与文件夹侧栏。桌面邮件页因此同时消耗：

- 248px 全局导航侧栏；
- 220px 邮件账号/文件夹侧栏；
- 页面外边距和两栏之间间距。

这会压缩邮件列表与详情的有效宽度，也让界面更像后台管理系统，而不是邮件客户端。

### 2.2 邮件导航状态依赖页面内部事件

当前移动端账号和文件夹切换链路是：

`AppSidebar -> App.vue -> flymail-mail-navigation -> MailList.vue -> switchAccount/handleMailNavigation`

这意味着应用壳想切换邮箱，却需要隐藏的邮件页面代为执行。随着邮箱和文件夹升级为全局永久导航，这种依赖会变得不合理。

### 2.3 桌面与移动存在重复邮件导航 DOM

桌面账号/文件夹位于 `MailList.vue`；移动账号/文件夹位于 `AppSidebar.vue` 的 `mobile-mail-navigation`。同一个信息架构维护两份模板和样式，容易产生后续行为和视觉不一致。

### 2.4 写邮件入口层级偏低

“写邮件”当前属于 `MailList.vue` 工具栏，因此只有进入邮件列表后才天然可见。它实际上是全局邮件动作，应当从联系人、同步管理、设置等任意页面可达。

## 3. 方案比较

### 方案 A：只搬 DOM

把 `MailList.vue` 的账号/文件夹直接搬进 `AppSidebar.vue`，其余事件和职责不变。

优点：改动最小。

缺点：应用壳仍然依赖 `flymail-mail-navigation` 和隐藏 `MailList` 执行账号切换；只是视觉合并，没有完成职责重构。

### 方案 B：邮件导航成为应用壳的一部分（采用）

`AppSidebar.vue` 直接使用 `mailStore` 展示和操作账号、文件夹；`App.vue` 负责页面导航保护和全局动作；`MailList.vue` 只监听 `mailStore.currentAccountId/currentFolder` 并刷新内容。

优点：

- 单一侧栏、单一账号/文件夹 DOM；
- 应用壳不再依赖隐藏页面；
- 桌面/移动一致；
- 现有 Pinia 状态可以直接复用；
- 改动边界仍然局限在前端应用壳和邮件页。

### 方案 C：只在邮件页显示邮件侧栏

管理页隐藏侧栏，页面全宽。

优点：管理页空间最大。

缺点：页面之间骨架跳变；用户离开邮件页后失去主要导航；不符合 `DESIGN.md` 的稳定应用骨架原则。

## 4. 最终信息架构

### 4.1 桌面侧边栏

展开宽度继续使用现有 `248px`，折叠继续使用 `72px`：

```text
FlyMail
+ 写邮件

聚合收件箱

邮箱账号
  工作邮箱
  QQ 邮箱
  Gmail

文件夹
  收件箱
  已发送
  草稿箱
  垃圾邮件
  已删除
  OA
  ROVO
  Teams

通知中心
用户头像
```

顶部品牌区、写邮件和聚合收件箱固定；中间账号与文件夹共享唯一纵向滚动区域；底部通知和用户菜单固定。

### 4.2 用户头像菜单

用户菜单承担低频功能导航，建议分组：

第一组：

- 联系人
- 同步管理
- 账号管理
- 邮件备份

第二组：

- 个人资料
- 签名管理
- 第三方通知
- 设置

管理员组：

- 用户管理（仅管理员）

尾部：

- 关于
- 修改密码
- 退出登录

不增加二级菜单，保持“头像 -> 目标功能”两次点击完成导航。

### 4.3 聚合收件箱

聚合收件箱仍属于邮件导航，不进入用户菜单。

- 用户设置开启时显示；
- 关闭时隐藏；
- 仅 `currentView === 'unified'` 时显示 active；
- 进入聚合收件箱不修改当前单邮箱的 `currentAccountId/currentFolder`，返回普通邮件时保留上下文。

## 5. 组件职责

### `App.vue`

负责：

- 当前一级页面 `currentView`；
- 导航保护（尤其签名管理未保存确认）；
- 桌面侧栏折叠 / 移动抽屉开关；
- 写邮件、选择邮箱、选择文件夹等全局导航动作；
- 聚合收件箱设置可见性；
- 页面合法性校验。

不再维护表示全部一级功能的 `navItems`。

### `AppSidebar.vue`

负责：

- 品牌和折叠；
- 写邮件入口；
- 聚合收件箱；
- 邮箱账号列表；
- 当前邮箱文件夹列表；
- 通知入口；
- `UserMenu`。

桌面和移动复用同一份账号/文件夹 DOM，不再保留 `mobile-mail-navigation`。

### `UserMenu.vue`

新增联系人、同步管理、账号管理、邮件备份入口，并保留现有个人、管理员和会话动作。

### `MailList.vue`

只负责：

- 邮件工具栏；
- 搜索、筛选、会话、多选；
- 列表、分页、详情；
- 回复、转发、附件、正文；
- 监听当前邮箱与当前文件夹变化并加载数据。

删除：

- 桌面 `.folder-sidebar`；
- `.account-switcher`；
- `.folder-nav-list`；
- `flymail-mail-navigation` 监听；
- 页面内部写邮件全局入口。

## 6. 状态与导航流

### 6.1 选择邮箱

从任意页面点击邮箱时：

1. 先调用 `requestNavigation('mail')`；
2. 如果存在未保存签名并取消离开，则停止，不修改邮箱状态；
3. `mailStore.setAccount(accountId)`；
4. `mailStore.loadFolders()`；
5. `MailList.vue` 通过现有 watcher 响应 `currentAccountId/currentFolder` 变化，重置搜索、详情、分页并加载邮件。

账号是持续的上下文状态，即使当前页面不是邮件页，也可保留轻量选中表现。

### 6.2 选择文件夹

从任意页面点击文件夹时：

1. 先调用 `requestNavigation('mail')`；
2. 离开保护通过后调用 `mailStore.setFolder(path)`；
3. `MailList.vue` watcher 重置列表相关状态并重新加载。

只有 `currentView === 'mail'` 时文件夹显示强 active，避免联系人、设置等页面仍错误高亮“收件箱”。

### 6.3 写邮件

侧栏“写邮件”由 `App.vue` 直接处理：

1. 使用当前 `mailStore.currentAccountId` 初始化新邮件草稿；
2. 调用 `requestNavigation('compose')`；
3. 继续复用现有 `ComposeEmail.vue` 和草稿状态，不改变发送逻辑。

无邮箱账号时写邮件入口禁用或明确不可用，主工作区继续提供“添加邮箱账号”引导。

### 6.4 重新授权

账号侧栏仍保留独立重新授权按钮。点击账号行进入邮箱，点击重新授权按钮只执行 OAuth 重新授权，不混合两个动作。

当前 `MailList.vue` 内的 `reauthorize()` 属于账号级能力，实施时抽到小型共享 composable，例如 `useAccountReauthorization.ts`。不重构整个 OAuth 架构。

## 7. 页面合法性

移除 `navItems` 后，页面合法性不再依赖导航 UI 数据。

使用显式页面集合或等价常量校验：

- `mail`
- `unified`
- `contacts`
- `history-sync`
- `accounts`
- `backup`
- `profile`
- `signatures`
- `notifications`
- `settings`
- `about`
- `users`（管理员）
- `compose`（特殊临时页面）

导航展示与页面合法性解耦，避免未来头像菜单调整影响路由状态校验。

## 8. 邮件页面布局

### 8.1 MailList

重构前：

`220px 邮件侧栏 + 邮件列表/详情`

重构后：

`邮件列表/详情占满 PageFrame 工作区`

`mail-shell` 从双列改为单列 `minmax(0, 1fr)`，释放约 220px 以上有效水平空间。

### 8.2 工具栏

“写邮件”从 `MailList` 工具栏移到应用侧栏。

桌面仍保留只读上下文摘要，例如：

`收件箱 · 未读 3`

它用于确认当前列表上下文，不承担导航职责。

移动端保留可点击的“当前文件夹 ▼”入口，用于打开统一侧栏抽屉，因为移动端没有永久侧栏。

## 9. 响应式设计

### 9.1 桌面

- 展开：248px；
- 折叠：72px；
- 保留现有 `flymail_sidebar_collapsed` 本地记忆；
- 折叠态显示图标、账号图标、核心文件夹图标；自定义文件夹使用统一 folder 图标并提供 `title/aria-label`。

不增加折叠态二级文件夹弹窗。

### 9.2 移动端

继续使用现有 960px 应用壳断点：

- 同一 `AppSidebar.vue` 变为 `position: fixed` 抽屉；
- 宽度继续 `min(88vw, 324px)`；
- 账号和文件夹不再有移动端专用模板；
- 点击邮箱、文件夹、菜单项后关闭抽屉；
- 保留遮罩、Escape 和关闭按钮；
- 390×844 不得产生页面级横向滚动。

## 10. 滚动与动态内容

遵守 `DESIGN.md`：

- 侧栏品牌、写邮件、聚合入口、通知、头像固定；
- 邮箱账号和文件夹共享一个 `overflow-y: auto` 滚动 owner；
- 邮箱名称、地址和文件夹名允许单行省略，保留完整 `title`；
- 用户菜单设置视口最大高度，内容过多时菜单内部滚动；
- 不允许侧栏动态内容撑宽应用壳或把底部用户区推出视口。

## 11. 空状态与异常状态

### 无邮箱账号

侧栏：

- 显示“邮箱账号 / 暂无邮箱账号”；
- 不显示文件夹列表；
- 写邮件不可执行；
- 聚合收件箱按设置决定是否显示。

工作区继续显示“暂无邮箱账号，请先在账号管理中添加邮箱”，并保留直接进入账号管理的操作，不要求用户理解头像菜单结构。

### 重新授权

账号行保留警告状态和单独的重新授权按钮；正常账号选择与重新授权操作互不替代。

## 12. 样式职责

负责：

- 应用壳网格；
- 新邮件侧栏布局；
- 账号列表和文件夹列表；
- 折叠态；
- 移动抽屉；
- 用户菜单定位；
- 侧栏滚动。

### `MailList.vue` scoped CSS

### `tokens.css`

## 13. 测试契约

自动化测试至少锁定：

1. `MailList.vue` 不再包含 `.folder-sidebar` 和 `.account-switcher`。
2. `AppSidebar.vue` 包含写邮件、聚合收件箱、邮箱账号、文件夹、通知和用户菜单。
3. 桌面与移动使用同一份账号/文件夹 DOM，不再出现 `mobile-mail-navigation`。
4. `flymail-mail-navigation` 全局事件被移除。
5. 联系人、同步管理、账号管理、邮件备份位于 `UserMenu.vue`。
6. 文件夹 active 只在 `currentView === 'mail'`。
7. 聚合入口只在 `currentView === 'unified'` active。
8. 248px 展开、72px 折叠、960px 移动断点继续成立。
9. 390×844 无页面级横向溢出。

11. 现有搜索、筛选、会话、多选、分页、详情、回复、转发、附件、同步行为无回归。

浏览器验证至少覆盖：

- 1440×900；
- 1920×1080；
- 390×844；
- 200% 页面缩放或等价字号增加。

## 14. 实施顺序

### 阶段 1：收口导航状态

- 将邮箱选择、文件夹选择、写邮件和重新授权从 `MailList` 页面事件模型中移出；
- 让 `App.vue` 直接协调 `mailStore` 和页面导航保护；
- 保证此阶段业务行为不变。

### 阶段 2：迁移邮件侧栏

- 将账号和文件夹模板迁入 `AppSidebar.vue`；
- 删除 `MailList.vue` 内桌面侧栏；
- `mail-shell` 改为单列。

### 阶段 3：迁移低频功能

- 联系人、同步管理、账号管理、邮件备份进入 `UserMenu.vue`；
- 删除旧 `navItems` 一级功能列表；
- 页面合法性改为显式集合。

### 阶段 4：统一桌面和移动

- 删除 `mobile-mail-navigation`；
- 同一侧栏 DOM 通过 960px 断点变成抽屉；
- 保留移动 MailList 的“当前文件夹 ▼”抽屉入口。

### 阶段 5：清理与回归

- 删除旧事件、旧 CSS 和无效接口；
- 更新布局契约测试；
- 做桌面、移动、极端内容和 200% 缩放检查。
