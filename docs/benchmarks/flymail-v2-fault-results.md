## 方法

`backend/tests/v2/test_fault_injection.py` 不增加生产故障开关，而是通过现有依赖注入、假 IMAP/SMTP/IDLE 传输、对象存储临时目录、真实 MySQL 事务和 Worker 租约运行生产路径。统一矩阵重跑分散在现有测试中的故障用例，并检查所有安全不变量都有直接覆盖。

执行命令：

```bash
cd backend
python -m unittest tests.v2.test_fault_injection -v
```

## 故障矩阵

| 场景 | 主要期望 |
|---|---|
| API 在事务提交前终止 | 草稿、操作、任务和 Outbox 全部回滚 |
| API 在提交后终止 | 已提交数据可在新连接和重启后恢复 |
| Worker 领取租约后、远端调用前终止 | 停止领取，取消超时任务并释放租约 |
| 远端操作完成后、本地完成前终止 | 不重复远端 APPEND/SMTP，进入明确不确定状态 |
| MySQL 在领取或完成时不可用 | 不丢任务，不把数据库错误误判为远端成功/失败 |
| 对象临时写失败或磁盘错误 | 不留下最终文件或临时垃圾 |
| 数据库引用后的对象文件缺失 | 返回明确 missing/corrupt 状态，不越权读取 |
| IMAP 正文/附件流中断 | 清理 fetching 状态，可安全重试 |
| SMTP 在 DATA 后断开 | 进入 verification，不直接重发 |
| Outbox 持久化后发布进程终止 | 业务状态、任务与事件保持事务原子性 |
| IDLE 半开与刷新超时 | 主动断开会话并恢复轮询 |
| 服务商限流风暴 | 有界退避，不阻塞其他服务商和账号 |
| 历史批次处理中收到 SIGTERM | Worker 安全关闭并释放资源 |
| 定时发送附近系统时钟调整 | 使用稳定绝对时间和持久化 available_at |

## 安全不变量

- 已提交任务不丢失。
- SMTP/远端 APPEND 不重复。
- 跨用户资源仍不可枚举或访问。
- 有引用的对象不被误删。
- 所有失败进入可恢复、永久失败或结果不确定等明确状态。
- 重启与租约恢复在测试边界内完成。
- 用户可见错误保持安全类别，不包含底层异常秘密。

## 实测结果

- 顶层故障矩阵测试：`3/3` 通过。
- 必需故障场景：`14/14` 覆盖。
- 被统一矩阵实际重跑的生产路径测试：17 个。
- 并发 `SKIP LOCKED` 双 Worker 领取测试：连续 20 次通过。
- 不变量失败：0。
- 生产混沌环境变量或后门：0。
- 用时：12.919 秒。

该结果证明确定性故障边界和恢复状态符合当前实现，但不替代真实服务商网络故障、宿主机断电、文件系统损坏或生产负载下的长时间演练。
