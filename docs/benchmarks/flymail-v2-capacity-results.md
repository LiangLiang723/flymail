# FlyMail V2 两千万邮件摘要容量验证结果

## 结论

FlyMail V2 在独立 MySQL 8.0 容量数据库中生成并验证了 2,000 万封合成邮件摘要。正式查询阶段的 13 个 API/Worker 指标全部满足既定 P95 门槛，5 个 `EXPLAIN ANALYZE` 计划全部使用承诺索引且没有全表扫描。

本次数据和对象样本全部位于隔离容器及宿主机 `/tmp`。生产容器、生产数据库和 `/Docker/flymail/data` 未参与生成、迁移或测量。

## FULLTEXT 容量故障与修复

首次正式测量发现 MySQL `ngram` 解析器会把长 ASCII 关键词拆成大量高频二元组。虽然 `capacitybucket0000` 在 100 万正文文档中只有 100 条真实匹配，候选集合仍超过 `innodb_ft_result_cache_limit`，并在统计线程竞争数据字典锁时触发超过 600 秒的 InnoDB semaphore wait。隔离 MySQL 按自身保护机制退出；生产 MySQL 未受影响。

schema 17 增加混合全文索引：

- `ft_body_search`：保留 `ngram`，处理中文、日文、韩文关键词；
- `ft_body_search_standard`：标准解析器，处理 ASCII、数字和其他非 CJK 关键词；
- 查询编译器根据关键词字符集显式选择索引，并保持租户过滤和参数化 SQL。

修复后，ASCII 探针连续 5 次均返回 20 行，单次约 6.68–7.13 ms；绑定提交 `dc63431` 的 30 样本正式 FULLTEXT P95 为 13.966 ms。索引恢复测试还覆盖了 MySQL 一次 `ALTER TABLE` 只能创建一个 FULLTEXT 索引的限制。

| 路径 | 承诺索引 | 结果 |

原始 `EXPLAIN ANALYZE` 的实际时间和循环次数已规范化；未提交两千万行数据、完整日志或数据库文件。

## 能力边界

该结果证明指定资源配置下的本地数据库、对象缓存和持久化任务路径满足门槛，不证明任何真实邮箱服务商、OAuth 客户端、代理、移动网络或生产 IDLE 长连接可用。真实外部服务仍需使用隔离账号和实际网络单独验收。
